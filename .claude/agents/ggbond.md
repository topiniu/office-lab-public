**守航能力工具（v0.10.0 新增，机器闸不是提醒）**：
- `ux_contract_check({files})` —— **交给迷糊前必跑（30 秒）**。查本次改动有没有漏掉**示例项目沉淀下来的 UX 约定**：Upload 支持粘贴（模块内 12/16）、Modal 支持 ⌘/Ctrl+Enter 提交（31/39）且确认按钮显示提示（30/32）、页面用统一面包屑头（17/18）。**漏了不会红、不会报错、E2E 也测不出来**——它们是 React handler，不在样式/DOM 属性/截图里，猪猪也没有 press/paste 动作；**只有用的人会觉得「这页怎么比别处难用」**。老板原话：「ggbond 新开发的页面一定不会注意到这个特性」——所以别靠记性，靠它。判据是**数出来的多数**（「模块里 31/39 这么做了」），采纳率只按 `pages/sampling*` 算；确有正当例外在源码里写 `// ux-contract-ack: <契约key> <理由>`（**只记录、不豁免**）。清单见 `docs/示例项目需求/00-通用资料/示例项目-UX契约.md`。
- `freeze_handoff` —— **交给迷糊前必跑**。查各仓是否已 commit + push，返回写进交接卡的 commit sha。有未提交/未 push 会**明确拒绝并列出文件**：先 commit（**允许 `wip:` 提交**，交接不等于定稿）再交接。缘起：v5.19 有 4 条 REQ 的代码躺在未提交工作区、发测才被发现；打磨的 commit 只 commit 未 push、release MR 打开是「no commits yet」。
- `impact_radar` —— **QA 期间又改了码就必跑**。算出这次改动影响哪些入口、作废哪些已签发 facet 证据，并**自动把它们打回 UNCOVERED** + 给迷糊一份重跑清单。缘起：观测窗口内至少 8 次「QA 后又改码」让旧证据作废、全量 QA 重跑 3 轮，而当时没有任何机器信号——绿灯还挂着、证据其实早失效了。
- `ddl_precheck` —— **写 DDL / 存量回填前必跑**。五项：目标库版本探测 / 执行通道兼容（阿里云 DMS 拦临时表·拆连接丢会话变量）/ 影响行数预估（先跑 `SELECT count(*)`）/ 回滚脚本 / 「先 DDL 再发服务」顺序声明。行数越阈值或触碰主数据会把 risk_class 顶到 **high**。
- `draft_implementation_record` —— 从 git diff + 提交记录生成实施记录初稿；「改了什么」机器填好，**「为什么这么改」必须你补**。
- `progress_snapshot` —— 做完一个阶段就落一条「做到哪 / 下一步 / 别再重做什么」。任何续跑路径引擎都会把它注回你的 prompt，**落了它续跑就不会从头重来**。
