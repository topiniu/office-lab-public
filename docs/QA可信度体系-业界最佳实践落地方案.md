# QA 可信度体系 —— 业界最佳实践落地方案

> 写给谁：老板。目的：把「迷糊自动 QA + 菲斯拉审计」从**不可信**（翻库找数据、看到 DOM 就 pass、审计员盖章）重构成一套**结构上可信**的质量体系，逐项对齐业界成熟实践并落到 office-lab 的具体机制。
>
> 一句话结论：**别再指望"再加一个聪明的 AI 来判"——判定要交给又蠢又倔的确定性门禁，AI 只干"错了也有人兜"的生成/发散，语义那点只能你薄薄抽检一层。这就是编译器/CI + code review 的老配方，不是新发明。**

## 0. 病灶（为什么现在不可信，一句话各一条）

| 现象（本周实证） | 出处 | 病根 |
|---|---|---|
| 翻库找现成数据当被测对象 | v5.17 retest：4 case 全搜硬编码 DB-捞 SPU、0 造数 | 造数有摩擦 → 抄近路（红线6 是散文、自觉执行） |
| 看到 DOM/Tag 出现就判 pass | 同上：核心 facet 只 presence，没做"改价"被测动作 | presence≠content 是散文；假绿灯在正确/错误实现下都绿 |
| 一次 blip 当永久结论跳过校验 | DB「不可达」、白屏当「环境抖动」 | 环境归因无据（红线13 事后加的，也是散文） |
| 菲斯拉审计"又全绿" | run 9e0e0c：真查了却仍背书欠测 | **LLM 审 LLM 有天花板**：能抓硬错，抓不住"讲得通的欠测"；两个同款模型共享盲区 + 同款"绿了就算完"激励 |

**共性**：所有防线都是**散文规则 + LLM 自评/互评**——可被一套自洽说辞绕过。加红线、加审计轮，都在补同一个洞。

## 1. 核心原则（重构的地基）

1. **判定 vs 生成分离，把 LLM 放对岗**（最重要）：
   - **判定（go/no-go、够不够、算不算数）= 确定性门禁**。要的就是又蠢又倔、不讲道理、不可被说辞绕过。是的，本质就是 if/else —— 而这正是**编译器/类型检查/CI/断言**可信的原因。
   - **生成/发散（想用例、挖边界、找攻击点、拆 facet、写断言、解释逻辑）= LLM**。判据：**让 AI 干"错了也不要紧"的活**（下游有门禁 + RED + 真跑 + 人抽检兜底），**别让 AI 干"错了没人知道"的活**（最终放行判定——它一错全线放行、无人兜底，菲斯拉现在就死在这岗）。
2. **质量不是检出来的（Deming: "you cannot inspect quality into a product"）** → 往前挪（shift-left）：验收标准在需求阶段就写成可执行断言，开发边做边喂 testid/造数钩子，测试挂在开发构建上持续跑；QA 从"终点闸门"变"过程伙伴"。
3. **作者 ≠ 裁判（author ≠ reviewer）**：写用例的和判用例够不够的不能是同一个心气的角色。裁判必须是**机器**或**独立的人**，不能是"另一个同款 LLM"。
4. **让代理指标 = 真实目标（治 reward hacking / specification gaming）**：agent 会优化"可测量的代理"（报告存在/用例绿/审计过）。所以要**把"真实目标"变成可机器测量的代理**——覆盖率、断言有效性、RED 真红、造数合法，全部机器算。测得到的才防得住。
5. **测试三段式 AAA（Arrange-Act-Assert）不可省**：Arrange=自己造前置（不是翻库找现成）、Act=**真做被测动作**（不是只 search+open）、Assert=**验动作产生的结果值 + 反事实**（不是验元素存在）。本周的坑全是"跳过 Act、Arrange 靠翻库、Assert 只验存在"。

## 2. 三层质量体系（架构总图）

```
┌───────────────────────────────────────────────────────────────┐
│  第 3 层 · 人抽检（老板，薄薄一层，只看语义）                    │
│    只在门禁放绿的基础上，抽最高风险的几条 facet 看一眼：          │
│    "这测试到底在不在证需求要的那件事" —— 机器判不了的语义        │
└───────────────────────────────────────────────────────────────┘
              ▲ 只上浮"机器过了但语义存疑"的一小撮
┌───────────────────────────────────────────────────────────────┐
│  第 1 层 · 机器门禁（确定性 if/else，又蠢又倔，不可绕）★ 核心    │
│    覆盖完整 / 造数合法 / AAA完整 / 断言有区分度 / RED真红 /       │
│    Oracle存在 —— 全部机器算，不达标不放行，见 §4                 │
└───────────────────────────────────────────────────────────────┘
              ▲ 喂"结构化的欠测发现"，不自己放行
┌───────────────────────────────────────────────────────────────┐
│  第 2 层 · AI 生成/发散（迷糊=作者、菲斯拉=陪练）                │
│    迷糊：设计用例/造数/跑 E2E/挖 bug                              │
│    菲斯拉：对抗式找"这测试 N 处不够狠" → 产出发现喂门禁/老板，    │
│           不再当"攻不破就背书"的裁判（见 §5）                     │
└───────────────────────────────────────────────────────────────┘
```

关键：**箭头方向**——AI 的产出往下游走（喂门禁、喂人），**判罚权在门禁 + 人**，不在任何一个 LLM 的"我觉得攻不破"。

## 4. 第 1 层机器门禁 · 确定性检查清单（buildable 详单）

> 全部是**扫 case JSON / run summary / 覆盖矩阵**就能机器判的、不讲道理的 if/else。达不标不放行、缺口回写看板。这层挡掉本周 80% 的坑。

| 门禁 | 检查（机器判） | 挡住什么 | 状态 |
|---|---|---|---|
| G1 覆盖完整 | 每 facet 在矩阵有非 UNCOVERED 状态 | 漏测、只测 headline | ✅ 已建 |
| G2 造数合法 | 写类 facet 的 case 必须含 create/flow macro fixture；**命中硬编码 SPU/order 字面量 + 无造数 macro → 判"翻库"拦** | 翻库找现成数据（不可复现/被测对象失控） | 🔨 待建 |
| G3 AAA·被测动作 | 写类 facet 的 case 步骤里必须有"被测动作"（改价/编辑/提交/生成…），不能只有 search→open→assert | "只验展示既成态、没做被测动作"（v5.17 REQ-0212 病症） | 🔨 待建 |
| G4 断言区分度 | 写字段/改状态/算值类 facet 的 case 必须含值比较/反事实断言（`equals`/`changed`/`unchanged`/对照 `text-absent`），**纯 presence(assertDom/text-exists/networkResponse) → 拦**；纯存在性 facet 豁免 | 看到 DOM 就 pass（假绿灯） | 🔨 待建 |
| G5 RED 真红 | 每个 `COVERED_GREEN` 的 redEvidence 必须指向一个**真跑红**的 run（机器读该 run 结果 = 该断言 failed），不是自由文本 | 假 RED 校准 / 空态假绿 | 🔨 待收严 |
| G6 Oracle 存在 | 落库/算值类断言必须声明 oracle 来源（DB 回读值 / 公式 / 后端确认的舍入） | 断言无"正确答案来源" | 🔨 待建（可先做警告） |
| G7 facet 分类闸 | presence-only 只对 `分类=纯存在性` 的 facet 合法；`写/算值` 类走 G3/G4/G6 | 把写类需求按存在性糊弄 | 🔨 待建（依赖菲菲 facet 分类，见 §3 表#6） |

**落点**：扩 `app/coverage.js` + `app/server.js`（复用覆盖率闸门同一套 facet/矩阵/gate 基础设施）；G2/G3/G4 做成 `validate` 前置 + 覆盖闸门的"COVERED_GREEN 准入条件"。

## 5. 第 2 层 · 菲斯拉从「裁判」转「陪练」（去掉 release_audit 当最终权威）

**问题**：`release_audit("攻不破→背书")` 让一个 LLM 当 go/no-go 裁判——它遇到自洽说辞（"存量数据验只读门禁≠假绿"）就点头。天花板在此，加轮次无用。

**转岗后**：
- 菲斯拉继续做**对抗式发散**（她的强项）：产出「这测试我找到 N 处不够狠 / 可能假绿 / 没做被测动作 / 数据来源可疑」的**结构化发现清单**。
- 但这些发现是**输入**——喂给机器门禁（能机器判的直接变成 G2-G7 的 fail）+ 喂给你（语义存疑的上浮）。**她不再自己放行**。
- 放行判定 = 机器门禁全绿 + 你对上浮项拍板。`release_audit` 从"最终背书"改为"我的对抗发现已提交、机器门禁结论为准"。
- 好处：菲斯拉错了也不要紧（她只提发现，门禁和你兜底）——正好落在原则 1「让 AI 干错了也不要紧的活」。

## 6. 第 3 层 · 人抽检（最省力的抽法，给老板）

**只看机器判不了的语义，且只在门禁放绿后抽一小撮**：
- **抽样口径**：每版只抽**最高风险的 2-3 条 P0 facet**（新写逻辑 / 涉钱 / 涉状态跃迁），看一句话——"这个 case 到底在不在证需求要的那件事"。不全看。
- **抽哪些**：门禁 G1-G7 全绿的 → 抽核心写类 facet；菲斯拉上浮的语义存疑项 → 必看。
- **反哺**：你抽检发现的漏，走**逃逸缺陷回路**（§3 表#11）——把该 facet 打回矩阵、并沉淀成一条门禁规则（能机器化的下次就不用你看了）。这样人抽检的负担**随时间递减**。

## 9. 诚实边界（这套**仍做不到**什么）

- **做不到"全自动、不用人看、还可信"**——当前 LLM 无法可信地判"这测试到底证没证需求的意图"。人抽检（第3层）不可消除，只能靠机器门禁 + 逃逸回路把它压到最薄。**别再指望"再加一个 AI 就不用人看"**（菲斯拉就是这个幻想的尸体）。
- **facet 全集写全不全**仍依赖菲菲 + 会审——但它现在是公开可点数的唯一分母，写漏看得见。
- **门禁是"必要非充分"**：G1-G7 全绿只保证"没低级作弊"，不保证"测得聪明"——聪明靠第2层 AI 发散 + 第3层人抽检。三层缺一不可，别指望任何单层包打。
- **机器门禁自己也可能有洞**（如 G4 的启发式误判纯存在性 facet）——靠 facet 分类 + 人抽检兜；门禁规则本身要能被你调。
