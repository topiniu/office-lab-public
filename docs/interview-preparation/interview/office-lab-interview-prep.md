## 1. 项目介绍背诵稿

### 30 秒

我做的是一个 AI 数字员工工作台：六个有明确职责和红线的 agent（PM、全栈开发、专业 QA、教导主任、DevOps、巡视员）在一个真实企业代码库上跑完整交付流水线。它们靠仓库里的 Markdown 任务档案做状态总线、靠收工汇报里的机器标记做交接，引擎负责会话生命周期、自动接棒、健壮性自愈和质量门禁。

核心不是「多开几个 Claude 窗口」，而是三件事：**让一支无状态 agent 团队在共享工作树上不打架、让「它说干完了」可被机器验证、让「它停下来了」不会静默。**

### 1 分钟

这个项目解决的是「AI 团队协作在真实生产仓库上不可信」的问题。它有三层：

**编排层**——四个交接标记加服务端强制守卫，以及一套把共享状态总线的写操作收归引擎的机制。这套机制不是偷懒，是被逼出来的唯一解：员工全跑在 bypass 权限下，SDK 在咨询权限回调之前就放行了，所以「用 canUseTool 拦截 + 加锁」那条自然路对它们全失效。

**监督层**——三条正交通道分别管进程冻死、模型空转、协作层该停没停，加上收工那一刻的机器校验。这一层有个数字：巡视员在观测窗口里被派 79 次、只有 2 次是真停，97% 的浪费来自「事后才发现收工没写标记」——所以我把那个纯字符串判定挪到了收工那一刻。

**门禁层**——QA 通过判定不再由 LLM 自评，而是引擎从真实测试产物机读签发，证据绑 runId、testHash、summaryHash 和 git commit，另有三个反模式 linter 挡在置绿那一刻。

技术栈是 Node 原生 http + Claude Agent SDK（npm 依赖只有两个）+ React 19 新 UI，加一套 vanilla 旧 UI 作免构建兜底。449 条单测，全部不启 server。

### 3 分钟

可以拆成五层讲。

**第一层是产物协议。** 核心信条是「产物永远在仓库文件里，Lab 只做调度与观测——删掉整个 `app/` 不丢任何数据」。任务档案是纯 Markdown，frontmatter 记状态和门禁，四个承重章节分别是需求条目登记表、覆盖矩阵、待确认事项和时间线。这条信条决定了后面所有取舍。

**第二层是编排。** 交接靠四个标记：下一棒、交回、等你拍板、教训。解析有三条铁律，每条对应一次真实事故——标记必须独占一行（指令正文里常引用标记名）、全文搜索取最后一条（长 prompt 会截掉真标记）、指令支持多行。服务端不信 agent 守规矩，有深度天花板、自环改自续、回发拦截、扇出闸。还有第三种原语「抄送」，做成回合**内**的工具而不是回合边界的标记，因为标记只在 result 解析、给不了「继续」。

**第三层是健壮性。** 三条正交通道：watchdog 管进程冻死、判据是零字节；空转熔断管模型层没产出、判据是 SDK 自催次数或零产出顶层轮次；巡视员 agent 管协作层该停没停。这层最值得讲的是一个反面教训——空收工第一版做的是「自动热推续跑」，当天回退，因为它锁住 running、让 `/reply` 恒 409，把「静默停但随时能继续」放大成「彻底不工作」。**修 A 类问题不能引入 B 类问题；能被动暴露 + 交回控制权，就不要主动接管。**

**第四层是门禁。** QA 可信度经历了四代：加红线没用、新建一个同质 QA 它给假绿盖了章、建对抗审计员她太会讲道理接受了自洽说辞，最后才想明白——**判定必须移出 LLM**。现在 facet 是一等可追溯单元，五种状态里没有一种叫「我判断不用测」，`COVERED_GREEN` 禁手填、只能由引擎从真 summary 机读签发。上线当天把历史矩阵重算成 34/34 gap，宁可诚实全红。

**第五层是无人值守。** 守航态有契约、三红灯台账、门禁矩阵、发布链七环对账、版本级晨检验收单。这一层最重要的设计决定是 **fail-closed 第三态**：外部平台的四个验证接口当时一个都没上线，最省事的实现是「拿不到就跳过」，但那会让假绿计数永远是 0——**纸面上「三灯全 0」和「从没统计过」长得一模一样**。所以引入 `unverified`：不计红灯，但也绝不算可信绿，并在每份产物里显式印出来。

### 5 分钟（在 3 分钟版基础上补三块）

**第一块：为什么这个项目的技术都是被协作事故逼出来的。**

我的复盘文档有 3500 行、每条都带起因/根因/对策/取舍/残留面。把它们归族之后会发现，最大的一族只有一句话：**把布尔判断托付给了模型的措辞。** 举三个：

- 写一条「等你拍板」就同时买断三道防线——pending 门短路在 QA 硬闸之前，所以闸门没算；闸门分支里挂着的对抗审计连带没派；巡视因为标记豁免根本没被叫醒。守航跑一夜 15 个 facet 拿到 0 个机器 GREEN，手机端一切如常。
- 写了「交回」标记但闸门 fail-closed 把它吞了（那条 run 从一条闲聊线漂下来、`taskFile` 是 null，闸门首行抛错走 catch 只落了一行日志就 return），而巡视因为「标记存在」当合法收尾放行。**标记的「存在」被当成了「执行成功」。**
- 空转闸的判据挂在「SDK 恰好会说的一句话」上（`[Your previous response had no visible output...]`），上游改成静默重发请求之后，闸门整条静默失效——**失效方式是静默的：闸门还在、代码还在、日志上什么都不缺，只是永远不触发。**

这一族复发四次之后收敛成一条原则：**判据要挂在本层能直接观测到的事实上，凡是托付给措辞的地方，引擎侧必须留一条不依赖措辞的旁路。**

**第二块：为什么「SOP 是软约束、工具才是硬约束」这句话我有 A/B 数据。**

我们对同一个 QA 角色做过十四轮增强，四种手法：加红线、新建角色、改判定成机器、做成工具。结果非常清楚——**凡是「改成机器判定/工具契约」的都稳住了，凡是「写进 SOP / 加红线 / 改派工文案」的都会被下一轮压力压穿。**

更狠的是最后一轮：查下去发现连「软约束失效」都不是——她**够不到**那些能力（配置里存的平台地址是个已死端口，导致 18 个 MCP 工具静默全缺），而系统还在骗她说「平台没做」（我们自己按命名习惯猜了个端点路径，404 之后把「我猜错了门」记成了「你没盖房子」，这个假事实沉淀了两周）。那一轮她判「登录必须人工介入」，空转 14 小时——而其实一次 `GET /auth/status` 就能终结它。

所以现在我加任何规则之前先问三件事：**这句话对应的机器答案存不存在？它够不够得到？够不到时系统会不会如实说「我不知道」？** 那一轮的答案是「存在 / 够不到 / 不会——反而报了假事实」。在那个输入集合下，她的推理是合理的。**追责推理之前先修输入，否则会一路修到「她怎么这么笨」，而那条路没有尽头。**

**第三块：诚实的边界。**

这个项目**没有**跨机调度、**没有** worktree 真并行（同员工不并发是刻意的，因为所有 run 共用一个工作树）、**没有**成本硬顶杀进程（夜里被杀死比超支更坏，改成记一条 `budget_unset` 让「没设硬顶」在晨检包里可见）、**没有** CI（这是个明确决定，理由我可以细讲）。

守航态首两轮真实跑完的结论我也照写进了文档：**行为纪律成立（不猜口径、不降标换绿、不碰生产），但结构缺席**——契约没有机器闸、证据绑的是可变工作区、共享环境没有产权边界。而且**两个真产品缺陷都是老板手工用出来的，不是 QA 测出来的**：一个是 React 事件池化在 updater 里读已回收的 `e.target`，一个是同一份数据在四个入口三套排序。根因两条：facet 全是单点行为、没有一条问「同一份数据在四个入口看起来一样吗」；平台 headless 不采 console/pageerror，「点一下就抛 TypeError」在 headless 里不可能变红。

这个结论不好看，但它是下一轮要做什么的唯一依据。

## 2. 简历项目描述

### 简洁版（2 行）

设计并实现 office-lab AI 数字员工编排工作台（Node + Claude Agent SDK + React 19），把六个有职责与红线的角色 agent 组织成面向真实企业代码库的软件交付流水线，以仓库 Markdown 为唯一状态总线、以收工标记为交接协议，支持自动接棒、健壮性自愈、权限三名单与无人值守守航态。

建设「让 AI 的结论可被机器验证」的门禁体系：把 QA 通过判定从 LLM 自评改造为确定性引擎判定（facet 覆盖硬闸 + 机器证据血缘 + 反模式 linter + fail-closed 第三态），并以 449 条单测与逐事故复盘（3500+ 行）支撑机制持续演进。

### 详细版（5 行）

- 负责工作台从 `spawn('claude -p')` 到 Claude Agent SDK 常驻流式 `query()` 的引擎重写，前后端契约（HTTP 端点 / SSE 事件 / run 形状 / 标记解析）零破坏；设计空闲窗对齐 prompt 缓存 TTL 的会话生命周期。
- 设计四标记交接协议与服务端强制守卫（深度/自环/回发/扇出/线程预算），并把共享状态总线的写操作收归引擎（per-file 锁 + 原子写 + 枚举校验）——这是全员 `bypassPermissions` 下唯一可靠的并发安全手段。
- 建设三层正交监督：进程层 watchdog、模型层空转熔断（双判据：SDK 自催次数 + 零产出顶层轮次）、协作层巡视员 agent（按被巡员工职责注入判据），并把「收尾有没有标记」这类纯字符串判定从事后巡视挪到收工那一刻（砍掉 79 次巡视里的 97% 浪费）。
- 主导 QA 可信度四代范式转移：加红线 → 建同质 QA → 建对抗审计员 → **把判定移出 LLM 变成确定性门禁**；v2 上线后如实把历史矩阵重算为 34/34 gap、`qa_passed=false`，宁可诚实全红也不兼容历史假绿。
- 完成两轮隧道性能整备（`/api/runs` 3586KB → 320KB(br) → 0KB(304)、四路轮询合流为一路、首屏文本压掉 ~70%），并沉淀「横切策略必须落在唯一出口」「隧道是放大镜」两条方法论。

### STAR 版

- **S**：一支 AI 员工团队要在真实企业代码库上做交付，最初的问题不是「AI 写不好代码」，而是——交接会静默丢失、停下来没人知道、QA 会「合理地」欠测、夜里跑一半冻死没有报告。
- **T**：让这支团队的**每一步都可观测、每一个结论都可验证、每一次停顿都不静默**，同时不把产物锁进任何私有系统。
- **A**：以仓库 Markdown 为唯一状态总线、四标记为交接协议建起编排骨架；用三层正交监督覆盖三类不同性质的停顿；把 QA 通过判定、发布交付物核对、守航越权计数全部下沉为确定性机器判定，并引入 `unverified` 第三态防止「问不到」被伪装成「通过」；两轮性能整备把隧道下的首屏与 API 开销压掉一个量级。
- **R**：449 条单测全绿、3500+ 行逐事故复盘、十一个版本连续演进；机制侧有明确量化（假绿式偷懒被机读门禁基本堵死、97% 巡视浪费被砍掉、API 传输降一个量级）。**业务侧的「一次通过率 / 交付周期」尚无统一基线，不编数字**——首两轮真实守航的诚实结论是「行为纪律成立，但结构缺席」，两个真缺陷都由人工使用发现而非 QA。

## 3. 高频面试题与答案

### Q1：这个项目解决什么问题？

不是「让 AI 写代码」——那是 Claude Code 本身解决的。它解决的是**「一支 AI 团队在真实生产仓库上协作时不可信」**：交接会静默丢失、agent 停下来没人知道、QA 会用「待人工/源码坐实/环境不可用」这类听起来合理的理由绕过真测试、夜里跑一半冻死连报告都没有。这些问题在单 agent 场景里都不存在，是多 agent + 长时间 + 真实代码库这三个条件同时成立才冒出来的。

### Q2：这跟 MetaGPT / ChatDev 有什么不一样？

它们是我的**组织结构对标**——角色化 AI 软件公司 + SOP，ChatDev 连「自动巡逻 bot」都和我的巡视员撞。但它们是 **prompt → 一次性吐个 app 的 demo 生成器**（贪吃蛇、小工具，~$2/次），**无持久任务档案、无人在环门禁、无真 repo/MR/发布**。架构上属「热单上下文一次性冲刺」派，快是因为省掉了我背的治理税。

**开源界并没有真正把「可审计、人在环、面向生产的持久 agent 舰队」产品化**——我做的那半边没有成熟对标，精英组织都是自己长出来的。这既是机会也是风险：没有前人踩过的坑可抄，所以我的复盘文档特别厚。

### Q3：这不就是多开几个 Claude Code 吗？

Claude Code / Agent SDK 是驱动层，复杂度在它之上的三处：

1. **让无状态 agent 团队在共享工作树上不打架**——所有 run 共用一个工作树、无 worktree 隔离，所以要有并发闸、跨线程待处理队列、共享总线写收归引擎。
2. **让「它说干完了」可被机器验证**——facet 覆盖硬闸 + 机器证据血缘 + 反模式 linter。
3. **让「它停下来了」不会静默**——三层正交监督 + 收工即校验 + 交接受阻升级。

而且有一条只有真做过才知道的坎：**员工全跑在 bypass 权限下，SDK 在咨询 `canUseTool` 之前就放行了**——所以「用权限回调加锁」这条看起来最自然的路对现有员工全部失效，把写收归引擎是唯一可靠手段。

### Q4：为什么状态总线是 Markdown 不是数据库？

第一性取舍：**产物永远在仓库文件里，删掉整个 `app/` 不丢任何数据。** 人和 agent 都能直接读写，可 diff、可审计、进 git，而且 agent 对 Markdown 的原生亲和度是真实优势。

代价我都栽过、也都有对策：自研 YAML 子集脆弱（对策是把「超出子集」变成显式错误，**这条还没做完**）、长表格的 `Edit` 锚点易因他人回写失配（对策是把写收归引擎的结构化工具，员工不再手 Edit）、并发写要串行化（per-file 锁 + 原子 temp→rename）。

如果重构我**不会**换数据库——换了要重写协作协议、失去 git diff 与可审计性。会换的是索引层（SQLite 索引 run 列表与跨 run 指标），但事实源仍是文件。

### Q5：支持并发吗？

要说清**并发单位**：

- **跨员工**：真并发。`liveRuns` 是 Map，`busyRunFor` 只挡「同一员工开第二条**可写**会话」。
- **同员工**：**不并发**，这是刻意的——所有 run 共用一个工作树，两条可写会话必然互相踩写。跨线程来消息走**待处理队列**串行排空。
- **只读咨询窗**：豁免并发闸（零写能力 → 工作树天然安全）。
- **抄送扇出**：单回合 ≤2、同线程并存活跃 run ≤4——`maxDepth` 只挡深度、挡不住广度，每 run 抄 2 人、8 层内可爆 256 条并行 run。
- **没有**跨机调度、**没有** worktree 真并行、**没有**单角色分身。

### Q6：agent 卡住了怎么办？

三条**正交**通道，各司其职、不该互相兜：

| 通道 | 管什么 | 判据 |
|---|---|---|
| watchdog | 进程冻死 / 连接中断 | 零字节（宽限 = 基础 150s + 思考预算 × 系数；`thinking_tokens` 心跳作存活信号） |
| 空转熔断 | 模型层这一轮有没有真产出 | SDK 自催次数 **或** 零产出顶层轮次 ≥2 |
| 巡视员 agent | 协作层该停没停 / 不该停却要干 | 按被巡员工的职责与红线注入判据（两轴） |

**这三层分开是有代价的教训的**：曾经有一次两道防线一起失效——空转闸的判据挂在上游一句话上被静默绕过，而巡视员判了、升级了，但推送被降噪守卫吞掉、还顺手盖上「已裁决」封存签名。**净效果是这次停顿彻底静默。**

### Q7：那空收工为什么不自动重试？

做过，**当天回退**。

自动续跑要占住 `running`、让 `/reply` 恒 409，把「静默停但随时能继续」放大成「**彻底不工作、连话都递不进去**」。而且 resume 的正是那条退化会话，每轮都空，2 次纠偏白锁十分钟、烧 token。

更根本的是一个误判被坐实：**`result` 空 ≠ 这一轮没干活**——它只表示最终消息没有文本，中途完全可能有文本 + 成功的工具调用（数据已落库），只是结束在思考块或工具调用上。据此自动续跑既误判又扰民。

现行是「被动暴露」：置 error 终态 + 红灯 + 推手机，**关键是 run 立即回到可交互态**，把恢复节奏交回用户。

### Q8：怎么保证 AI 的 QA 不作弊？

**四代范式转移**，前三代都失败了：

1. 加红线 → 同类 bug 后续仍漏。洞察：**「写进记忆库的教训」和「开工前强制门禁」是两回事**。
2. 认定「规则过载」新建一个高信噪比的 QA → **它后来给假绿盖了章**。
3. 重定位为对抗审计员（目标函数设成「证伪」而非「复跑」）→ **她太会讲道理**，接受了自洽说辞。
4. **判定移出 LLM**（有效）：facet 五态里没有一种叫「我判断不用测」；`COVERED_GREEN` 禁手填、只能机读签发；证据绑 runId/case/testHash/summaryHash/commit/env；`qaTrace` 三段携带同一实体引用；`lintAck` 不再豁免；全路径 fail-closed；取消 LLM 最终放行权。

老板那句「菲斯拉改成机器门禁，那不就是 if/else 吗？」正是要点——**最可信的质检（编译器/类型检查/CI/断言）全是 if/else，正因它蠢、确定、不讲道理，才不可能被说辞绕过。**

三层分工：**判定 = 确定性机器 / 生成发散 = LLM / 语义 = 人薄抽**。判据是：**让 LLM 干「错了有人兜」的活，别让它干「错了没人知道」的活。**

### Q9：机器全绿就没问题了？

**不是。** 某版 17/17 全绿 + RED 完整，两个真缺陷都是人手工用出来的。根因两条：

1. **facet 全是单点行为**，17 条里**没有一条问「同一份数据在四个入口看起来一样吗」**——缺跨入口一致性这类横向 facet。
2. **平台 headless 不采 `console` / `pageerror`**，也没有「无 JS 报错」断言类型 → 「点一下就抛 TypeError、整页白屏」这类崩溃**在 headless 里不可能让用例变红**。

所以我的口径是：**「假绿式偷懒」已被机读门禁基本堵死；剩下的是「软性回避真跑」和「facet 全集本身的盲区」，靠机制点名 + 人抽检兜、非零风险。**

### Q10：加规则有用吗？

有条件。我有一条三问，是十四轮增强之后总结的：

> **这句话对应的机器答案存不存在？它够不够得到？够不到时系统会不会如实说「我不知道」？**

有一轮的答案是「存在 / 够不到 / 不会——反而报了假事实」。在那个状态下，写多少 SOP 都会被**观测到的「事实」**压过去。所以：

- 机器答案存在且够得到 → **做成工具/门禁**，别写 SOP。
- 机器答案存在但够不到 → **先修接线**，别加规则。
- 机器答案不存在 → 这才是 SOP/判断的地盘，但要**承认它是软约束**。

### Q11：性能问题怎么排？

**先量化再归因。** 首屏慢的直觉容易赖到「引擎/SSE/后端」，但逐层量字节就发现是三处纯静态浪费（头像 2264KB、文本资源零压缩、静态资源零缓存头），与业务逻辑无关。

第二轮更有意思：半年后同一类浪费**原样复现**——`/api/runs` **3586KB 明文**、被**四路并发轮询**（≈11~14MB / 15s）、而隧道指的还是 dev server（远程每开一次页拉几百个未打包 ES module，而 `dist` 早就构建好躺在那儿没进程服务它）。

**根因是「只治了看得见的那半边」**：第一轮的压缩挂在静态文件分支，而所有 `/api/*` 走的是另一个出口 `json()`。所以沉淀了三条：

1. **横切策略（压缩/缓存/限流/轮询）的落点必须是唯一出口**，不是「当前看到的那几个分支」。
2. **轮询是会自己繁殖的**——每个组件「顺手」加一行 `usePoll('/api/runs')` 都局部合理，四处合起来就是 14MB/15s；**横切关注点必须收在 hook 层做合流，靠 code review 逐处提醒治不住**。
3. **「本地开发怎么跑」和「远程怎么访问」是两个问题**——dev server 上隧道这种事，本机一点感觉都没有。**隧道/弱网是放大镜。**

### Q12：为什么现在比以前慢？

**这是机械事实，不是错觉。** 系统里一切只增不减：任务档案版本内越滚越大（曾 227KB / 462 行）、红线/SOP 每出一次事故加一条、连「每个优化都要留记录」都被写进硬门槛。**每回合税随时间单调上涨——系统被设计成越用越慢。**

但要说清杠杆排序（这一条我自己订正过一次）：一个 turn 的墙钟 = prefill + 生成 + 工具往返，**注入体积只影响 prefill**，而缓存命中≈瞬时。粗算一次冷启动周边事务 ≈30–90 秒且**主要是工具调用**（读档案/探环境）不是 token 预填，一版 10–20 次 ≈ 5 天墙钟的 0.1–0.5%，缩体积只攻其中一小块 → **实际 <0.1%**。

所以真杠杆排序是：**减跳数（快车道分级）＞ 减停顿（门禁/人在环）＞ 减返工 ＞ 不重探环境 ＞ 缩注入体积**。缩体积是**成本 + 质量杠杆，不是提速杠杆**。

### Q13：安全风险有哪些？

最紧迫的是**本地 HTTP 无鉴权且默认绑所有网卡**——同网段任何进程可触发派工（起真实 agent 改代码）、读写仓库文件。`OFFICE_LAB_HOST=127.0.0.1` 可锁回本机，但那砸掉「手机走隧道访问」这个真实用法。**这是我的 P0-1。**

第二个是**全员 bypass 下只有 deny 名单恒生效**，而 deny 的 glob 规则是**实测踩出来的、写在注释里**（必须用 `./x/**` 或 `//abs/**`，无前缀/单斜杠不匹配）——SDK 升级可能变，是明确的脆弱耦合点。会议室那次刻意改用**裸工具名** deny 就是为了绕开它。

已做的：`DANGER_DENY` 恒生效、非编码角色 code-lock、只读窗**一个 MCP 都不挂**（比逐个 deny 可靠，实测 SDK 直接答 not enabled）、企微人格无文件系统权限、凭据脱敏、`safeResolve` 各候选按其基准根限界。

### Q14：你会怎么衡量效果？

**先说不衡量什么**：我不会拿「覆盖率数字」或「机器 GREEN 数」当质量证明——某版 17/17 全绿而两个真缺陷都逃了。

**已经在埋的三类指标**：
- **A 硬红线计数（目标必须 0）**：越权动作数、超预算数、假绿数、超返工上限仍继续跑数。
- **B 行为分布（判护栏是否在工作）**：park 率、隔离率、资格误判率、证据完整率、空停时长。
- **C 效率与协同**：派工→首次实质动作时间、开工前工具调用次数、开发↔QA 时间重叠率、交接等待时间、下游因交接缺失退回次数。

**最终只认两个业务指标**：① 任务进入执行 → 测试环境可用的墙钟时间；② **人工验收后发现的逃逸问题数**。**速度上升但逃逸问题明显增加，不算成功。**

**诚实的现状**：A 类三个计数**目前只有一半是机器算的**（另一半依赖外部接口，走 fail-closed 记 `unverified`）；业务侧两个指标**尚无统一基线，我不编数字**。

## 4. 深挖问题与答案

### 为什么交接协议是「文本标记」而不是结构化工具调用？

历史原因 + 一个真实好处 + 一个真实代价。

**历史**：v0.1 时代引擎是 `spawn('claude -p')`，只能从收工文本里解析。

**好处**：标记落在**收工汇报**里，所以它同时是「给人看的交接说明」和「给机器读的指令」——一份产物两用，而且老板在聊天窗里能直接看到「它打算交给谁、交什么」。改成工具调用的话，交接意图就藏进工具参数里了。

**代价（就是族 A 那一整族）**：**把布尔判断托付给了模型的措辞。** 措辞可以缺、可以错、可以被上游换掉。修法不是废掉标记，而是**在引擎侧给每个「靠措辞触发」的判断都留一条不依赖措辞的旁路**——`handoffBlockedSig`、`qaHollowStopSig`、`patrolEscalating` 的白话兜底、`barrenTurns` 的事实判据，都是这条原则的落地。

如果重来我会**两者都要**：结构化工具调用作权威、文本标记作人可读的镜像，并让引擎校验二者一致。

### 「等你拍板」为什么会买断三道防线？

因为**三个不同的机制都把它当「跳过」条件读**，而没人把「谁在读它」列全：

1. `autoChain` 的门优先分支：`if (parsePendingGate(result)) return` —— 位置在 QA 硬闸**之前**，所以闸门根本没算。
2. 闸门分支里挂着的对抗审计派生：闸门没跑 → 连带没派。
3. `patrolEligible`：`parsePendingGate` 命中直接 `return false` → 巡视**根本没被叫醒**（不是判错了）。

**修法不是把门改成「不停流水线」**——有真待拍板事项时停是对的，**问题从来不是「停」，是「停了没人复核」**。所以只加一道复核：pending 门仍然停，但「挂档案的 QA 收工」在 return 前先把覆盖率算出来落档（只算不放行），未达标盖持久签名 → 巡视据此不再豁免。**覆盖真达标 + 有待拍板 = 合法请示，照旧豁免**（别惩罚干完活才问的）。

**审计任何「有 X 就跳过」的判断时，要把「谁在读 X」列全。**

### 巡视员为什么是一个 agent，不是引擎规则？

因为「这次停得对不对」**本质模糊**。同一批停顿里**有真该问老板的**（模板选型、关键发现），也有纯空停（末轮「我继续」）。规则区分不了。

但**检测**是确定性的、零成本的——引擎在 `autoChain` 三分支全落空处标出「候选空停」。所以做成**分层**：**便宜的判定交代码、贵而模糊的判断交模型。**

后来又发现一件事：**判据必须和被监督者的职责耦合**。它原本只有通用的「有没有停、有没有问」信号，于是出了两类方向相反的误判——QA 把「深层 facet 没测完」包装成「要我继续吗」被当合法请示升级给老板；而如果 DevOps 停下说「我需要 force-push」，按旧规则可能直接 resume 它进一个越红线的动作。修法是从每个员工的 SOP 里抽一段「巡视判据速查」注入巡视 prompt，并把判断从一轴（该不该停）扩成两轴（**该干没干 / 不该干却要干**）。

而 v0.10.0 又把它的职责**净化**了一次：把「收尾有没有标记」这类纯字符串判定挪到收工那一刻当场拒收，巡视只剩四类**真需要判断**的模糊态。**它从「守门员」变回「裁判」——这才是 LLM 该干的部分。**

### 为什么会议室不复用 run 骨架，而只读咨询窗复用了？

这两个决定是**相反**的，而且第二个明确修正了第一个的教条化表述。

**会议室另起旁路**，因为它与流水线**正交**：① 会议发言里出现「下一棒把这条交给某某」这类**自然语言**，走 autoChain 会被误解析成真派工；② 会议发言天然「说完就停」，会被 watchdog 当空停、被巡视当「该干没干」、被审计当 QA 结论去证伪——**全是噪声与误判**；③ 会议是**严格串行**，不需要常驻 query / 空闲窗 / 无感排队那套。所以只复用「原语」（工牌人格、一次性 query、落盘、渲染），**query 完全不进 runs 注册表**，于是不必在那些机制里到处加「if 会议则跳过」的特判——**那才是会腐烂的耦合。**

**只读咨询窗复用骨架**，因为它要的是**完整聊天体验**：流式 transcript、附件、OLCards、历史翻页、置顶/删除、会话切换、SSE 断点续传、无感排队。另起旁路等于把 800 行的聊天组件和整个流式 hook 全再实现一遍。而守卫是**集中的**：7 处，全都在既有函数入口一行 `if (isConsult(run))`。

**所以判据升级成**：「另起旁路 vs 复用骨架」取决于**复用面的大小与特判的分布**——特判少且集中就复用；特判会散进业务分支、或复用面只有一两个原语，就另起旁路。**别把「宁可另起旁路」当无条件教条。**

### `unverified` 第三态为什么这么重要？

因为**纸面上「三灯全 0」和「从没统计过」长得一模一样**。

背景：守航要统计三个「必须为 0」的红灯，其中「假绿数」依赖外部平台的四个验证接口——而写这一层时它们**一个都还没上线**（实测探活六个端点全 404）。最省事的实现是「拿不到就跳过」，但那会让假绿计数**永远是 0**。

**而这恰恰是要治的病**：上一轮的诊断就是「三个必须为 0 的红灯一次都没被机器统计过」。所以**不能让一个新建的指标一出生就自带一个虚假的健康值——它比不建更坏，因为它把「我们不知道」伪装成「我们很好」，从此没人再去建真的那一版。**

落到实现上有几个具体形态：
- `preflightGates` 返回 **`ok: null`** 而不是布尔——**就是为了让调用方没法把它当 `false` 或 `true` 用**。
- 缺位的 GREEN 记进 `unverified` 数组（不计红灯、也不算可信绿），渲染时显式印「假绿只算了引擎自己能算的那一半」。
- 环境指纹整体陈旧 → 可信度**直接判 0**，不是逐条打折（逐条打折会把整批不可信粉饰成「大部分可信」）。
- 晨检包有一节专门印「本轮哪些机器门是开的」，看板设置页有「探活一次」按钮 —— **界面上看不见哪些缺位，人就会默认「应该都通了」，于是「未验证」被读成「通过」，假绿又回来了。**

**这条口径的适用面远超守航**：凡「引擎去问一个外部系统、据答案下门禁结论」的地方，都该有第三态。

### 那 RED 校准为什么不 fail-closed？

好问题，这里方向**相反**，是刻意的。

「未验证 ≠ 通过」适用于**我们在声称某件事已被验证**的场合（假绿）。但 RED 校准如果直接判「不校准」，**今天所有 QA 轮会一夜之间全签不出 RED**——那是真回归，因为平台的结构化字段还没上线，谁也拿不到。

所以选了**第三条路：降级但留痕**。证据串里多一个 `redBasis=title-regex`，把这些 facet 单列成「RED 校准走了正则降级」，返回也直说「别据此认为后门已关」。

**通用形态**：当一条新判据的依赖还没到位、而旧判据不能直接拿掉时，第三条路是「用旧的、但把这件事标出来」。**最坏的做法是悄悄用旧的还宣称已经换了新的**——那正是这一版反复在治的病，只不过换成了我们自己犯。

### 「同一个 bug 修了三次」是怎么发生的？

指覆盖矩阵段定位那颗雷（它咬了三个会话）。

**第一次**：writer 的正则非锚定，任务档案时间线里只要有一句散文内联了「## 覆盖矩阵」就被劫持。**而那句散文恰恰是上一轮记录这个 bug 的时间线，自己带了裸标题触发它。** 加了行首锚定。

**第二次（次日又崩）**：两个独立原因叠加——① **补丁写盘 ≠ 生效**（线上跑的还是旧代码，用已提交版复现，报错栈逐字命中）；② **行首锚定本身治标**：一旦散文把标题写成**独占一行**（巡视 note、markdown 引用标题都会），它同样满足锚定条件、照样劫持。

**根因（本质）**：把「哪一段是覆盖矩阵」**锚在标题字面上**——而标题字面在正文里**可被合法复述**、天然不唯一。

**第三次（治本）**：改「按 facet 表头行认真段」——逐个候选标题，看其正文里有没有表头行 + 分隔行，只认有表头的那一段。reader 与 writer **统一走它**。

**三条教训**：① 锚点要锚在「目标独有且正文不可合法复述」的结构上；② **修解析坑要 reader/writer 一起改**；③ **治标补丁要在复盘里标注残留面**——第一次的对策断言「彻底忽略」把边界写死了，**反而掩盖了独占行这一类**。

### 为什么不做 CI？

抽取器实测 ~650ms/次，够便宜挂在流水线上。选引擎而非 CI 的理由是一句话：

> **CI 只会告诉前端开发「契约变了」——而他本来就知道，他就是改的人。真正需要这条信息的是下游写用例的 QA。引擎算 diff 并注入她的系统提示，是把信息送到消费者面前。CI 在这里是对着错误的人喊。**

**触发点也选得刻意**：选在「开发收工」而不是「派工 QA」——① 他是唯一会改前端的员工，且流水线顺序是开发 → 人工预检 → QA，所以她开工时契约必然已是最新；② 这样**不必在任何派工路径上 await**（`createDispatchRun` 有十余处同步调用点）。兜底再加开机一次 + 巡视 sweep 顺带。

**fail-soft 三层**：仓不在本机 → 静默跳过；抽取器报错 → 块里如实写失败原因；产物读不出 → 只给错误块。**绝不挡派工、绝不静默假装成功。**

（如果将来真要做 CI，定位应是「跑单测 + 类型检查」，而不是「契约漂移告警」。）

## 5. 项目亮点包装（每条都带残留面）

| 亮点 | 一句话讲法 | 残留面（**必须一起说**） |
|---|---|---|
| **判据挂在事实上** | 「空转闸原本挂在 SDK 恰好会说的一句话上；上游改成静默重发后，闸门还在、代码还在、日志什么都不缺，只是**永远不触发**」 | 三个实现细节任一错了新闸就变成新的误报源（按 message.id 归并 / 只数顶层 / 阈值 >1） |
| **判定移出 LLM** | 「最可信的质检全是 if/else，正因它蠢、确定、不讲道理，才不可能被说辞绕过」 | 只覆盖「进了矩阵/facet_doc 的 facet」；facet 全集本身的盲区（横向 facet）仍靠人 |
| **fail-closed 第三态** | 「一个新建的指标如果一出生就带着虚假的健康值，它比不建更坏」 | 假绿计数目前只有一半是机器算的；RED 校准仍走正则降级 |
| **SOP vs 工具的 A/B 数据** | 「凡改成机器判定/工具契约的都稳住了；凡写进 SOP 的都会被下一轮压力压穿」 | 不是所有判定都能机器化——语义（证没证需求意图）留人薄抽，且**人抽检不可消除** |
| **加规则前的三问** | 「机器答案存不存在？够不够得到？够不到时会不会如实说不知道？」 | 第三问的落地（探不通显式标红）目前仍是**软提示不是硬门禁**（守航态硬挡会 strand） |
| **共享总线写收归引擎** | 「员工全 bypass，SDK 在咨询权限回调前就放行——所以『加锁』那条自然路对现有员工全部失效」 | 仍是串行；真并行要 worktree（只做了 `worktreePlan`，**自动建树误判代价是丢代码**） |
| **横切策略落在唯一出口** | 「治了静态资源就宣布首屏整备完成，而 API 走的是另一个函数、另一条路，半年后原样复现」 | `/history` 与 SSE 冷开仍是「整文件读进内存再切片」 |
| **交付形态的验收要在交付形态上跑** | 「33 个被引用的文件从未入库——在源机器上完全不可见，在任何静态检查里也不可见」 | **macOS 真机首启未验**；三个 L→P 咽喉靠注释+测试保证，新增入栈路径忘了改写会静默出错 |
| **门禁上线前先跑存量** | 「异常高的那一组通常不是违规者，是判据没覆盖到的一类合法形态」 | 这条纪律目前只在一个门禁上执行过，没做成流程 |

## 6. 项目不足的体面回答

**问「这个项目最大的问题是什么」，我会答三条，按「会不会自己恶化」排**：

**第一，唯一必然恶化的债是产物治理。** `runs/` 曾达 291MB，没有 retention policy；任务档案在版本内只增不减（曾 227KB）；SOP/红线每出一次事故加一条。**系统被设计成越用越慢**，这是架构固有代价（无状态 agent + 磁盘协调）换来可审计性的另一面。方向清楚（分档归档 + 档案拆当前态头/时间线 + 红线退役纪律），但**没做**。

**第二，`server.js` 是 8770 行单文件。** 路由是 if 链、顺序是隐式契约；`autoChain` 一个函数塞了五种职责；`import` 即 `listen` 导致纯函数不能直接单测——现有回归只能「按名从源码抠出定义再 eval」（抠不到即抛错，重构改名会立刻红，可用但脆弱）。新能力已经在往外抽（16 个纯函数模块 + 依赖注入，449 条单测的基础），但主体没回头拆。**我知道该怎么拆，也知道第一步应该是把 `listen` 挪进 `main()`——那一步风险最低、收益最大。**

**第三，「守航可信」目前只有一半是机器算的。** 依赖的四个外部验证接口未全部上线，所以假绿计数走 fail-closed 记 `unverified`。**我认为这个处理是对的**（比 fail-open 报 0 好得多），但要诚实说：**它现在是「知道自己不知道」，不是「知道」。**

**如果面试官追问「那你觉得做得最不好的技术决定是什么」**：

第一版 Stage 4 契约拦截层——「守航态强制非 bypass + 落权限回调就一刀机器拒」。它把**只读 MCP 工具也误杀**了，PM 第一步就读不到需求表，夜里跑的会话直接卡死。**当场撤销。** 教训是：**结构门必须精准区分「只读安全工具 vs 危险/外部副作用」，一刀切 = 误杀正常工作。** 后来的三红灯改成**只计数不拦截**，拦不拦交给门禁矩阵与恒生效的 deny 名单。

## 7. 技术难点讲解（四个，都能讲 5 分钟）

### 难点一：让「模型停下来了」这件事永不静默

**为什么难**：停顿有三种完全不同的性质——进程冻死（零字节）、模型层没产出（result 空但可能中途有工具调用）、协作层该停没停（模糊，要读语义）。用一套机制兜必然出错：watchdog 兜不了「每个 turn 都正常收 result 但内容为空」；空转熔断兜不了「正常收工但没写标记」；巡视兜不了「进程冻死」。

**怎么解**：三条正交通道 + 一条收工那一刻的机器校验。**关键是判据的选择**，而不是阈值。空转判据从「SDK 恰好会说的一句话」换成「这一轮到底有没有产出 text/tool_use」，是这个项目最重要的一次判据升级。

**残留面**：巡视判断准头无量化基线；`liveRuns` 在内存，重启丢审批挂起态。

### 难点二：让 LLM 的「我测过了」可被机器验证

**为什么难**：QA 的成功定义是「产出合理报告 + 得出结论 + 交出去」，在这个目标下「待人工/源码坐实/环境不可用」每一个都是通往 done 的**局部最优省力动作**。而加规则只是增加它可套利的说辞面；加审计员只是让另一个可被话术糊弄的 LLM 盖章。

**怎么解**：把「通过」的定义收紧成一条**机器可算的公式**，且这条公式的输入必须是**机器事实**（真 summary + 哈希 + commit），而不是 agent 的自述。五种状态里**没有一种叫「我判断不用测」**，`lintAck` 不再改变严重级别（等于取消自批），三个反模式 linter 挡在置绿那一刻。

**残留面**：`SOURCE_ATTESTED` 仍可回避真跑（已用「同 REQ 有真绿 → 机读点名」收紧，但**判据是启发式**）；facet 全集本身的盲区；平台不采 console/pageerror。

### 难点三：让一支无状态 agent 团队在共享工作树上不打架

**为什么难**：所有 run 共用一个工作树、没有 worktree 隔离。而**员工全跑在 bypass 权限下，SDK 在咨询 `canUseTool` 之前就放行了**——所以「用权限回调拦截档案写 + 加进程内 advisory 锁」这条看起来最自然的路**对现有员工全部失效**；bypass 下仍恒生效的只有 deny 名单。

**怎么解**：把共享总线的写**收归引擎**（结构化工具 + per-file 锁 + 原子 temp→rename + 枚举校验），引擎持磁盘为准、**无「锚点」概念** → 同时根治「并发 clobber」和「长表格 Edit 锚点失配静默失败」两类竞态。加上并发闸（按员工挡写会话）+ 跨线程待处理队列（同线并入、跨线入队、收工排空）。

**残留面**：仍是串行；抄送扇出要额外两道闸（`maxDepth` 只挡深度挡不住广度）；worktree 真并行**未做**（自动建树误判代价是丢代码）。

### 难点四：让一个仓库真的「搬到别的电脑就能跑」

**为什么难**：读代码读不出来。看起来只有两件事（路径根 + 依赖声明），实际有三类性质完全不同的问题——一个设计缺陷（`ROOT` 同时是「拼路径的基准」和「agent 的工作树」，**前一个用途下凑巧能用，后一个用途下它是越权面**）、一个假声明（README 里的「零依赖」）、和**一堆从未入库的文件**（33 个，漏 `git add`，在源机器上**完全不可见**）。

**怎么解**：L/P/R 三层路径语义（**冻结 `office-lab/` 前缀这个线上协议常量**，只在出栈给 agent 那一刻改写一次，三个咽喉）+ 形态探测用标志物 + 「嵌套同名时改写恒等」写成断言 + bootstrap 的**仓库完整性自检**（解析 server.js 的本地 import 逐个查存在，缺就硬失败并直说「这是仓库本身不完整，不是你的环境问题」）。

**最重要的一条**：**凡是「交付形态」的验收，都要在交付形态本身上跑，不能在开发形态上推演。** 真 clone 两份（其中一份改名）跑一遍才照出全部问题。

**残留面**：**macOS 真机首启未验**；三个咽喉靠注释 + 测试保证，无机器检查。

## 9. 自我交底：我判断错过的地方

**这题千万别答「没有」。** 主动交底至少四条，而且每条都要说清「怎么发现错的」：

1. **把 testid 契约 CI 门禁推荐为「最狠的一刀」——靶子实测只占 3%。**
   我拿「定位类失败占 48%」这个错误码字面统计当了根因。修正它的动作只是一句「把失败的 testid 拿回源码里对一下」——实测 92% 是「元素当时不在页面上（状态没到）」，真·定位漂移只有 8%；而按定位手段算失败率，`testId` 步 2.4% 反而**最低**。**便宜的交叉验证要在提方案之前做，不是之后。**

2. **Windows Terminal 控制台移交那套解释——实测五分钟就否掉。**
   为了解释「关掉那个终端窗口整个程序就没了」，我先给出了一套严丝合缝的解释（默认终端已是 WT，控制台被移交给 `WindowsTerminal.exe`，所以隐藏失效）。实测三条正式入口都不留窗口。真凶是托盘对 web 端口「只旁观不接管」（`if (busy) { log; return }`）。**能被一条命令验证的假设，别拿它当结论。**

3. **提议删掉 61% 的 testid 注册表——把「组织方式差」当成了「内容冗余」。**
   实测那些「按版本追加」的段落里，**纯清单章节 0 节**；34 节是「清单 + 注解」混合，每段都夹着机器抽不到的东西（AntD 组件不透传 testid、「审价每行必填重量、与报价同为必填、易漏」、菜单文字来自后台配置…）。做之前先让机器逐段判了一遍才没删错。

4. **把「缩注入体积」列为提速主路——量化后收益 <0.1%。**
   老板质疑之后我重算：一个 turn 墙钟 = prefill + 生成 + 工具往返，注入体积只影响 prefill 而缓存命中≈瞬时；一次冷启动周边事务的大头是**工具调用**（读档案/探环境）不是 token 预填。**我当时把两件事缝错了**：注入体积（弱杠杆，是成本 + 质量）和员工前置行为（这才是看到的「慢」）。**订正后的排序是：减跳数 ＞ 减停顿 ＞ 减返工 ＞ 不重探环境 ＞ 缩体积。**

**外加一条自己造的 P0（不是判断错，是没读代码就接通了输入）**：把条目账接通之后，一条**长期沉默的顺延路径**首次触发，**把 PM 写的实质口径整段覆盖成了「deadline 到点未达」**。原文只在当轮包里还留着，据此恢复。
**教训：给一条长期沉默的代码路径接上输入之前，先读一遍它被触发后会写什么。「它一直没跑」不等于「它跑起来是对的」——恰恰相反，从没跑过的路径没有被任何真实数据检验过。**

## 10. 面试前 30 分钟速览卡

**五个数字**：8770 行引擎 / 449 条单测 / 6 个角色 / 3532 行复盘 / `/api/runs` 3586KB→320KB→0KB。

**五个必背的一句话**：
1. 判据要挂在本层能直接观测到的事实上，不是别人给的信号。
2. SOP 是软约束、工具与门禁才是硬约束；能被绕过的规则等于没有。
3. 修 A 类问题别引入 B 类问题——能被动暴露 + 交回控制权，就不要主动接管。
4. 「未验证」绝不能被写成「通过」；「我猜错了门」绝不能被写成「对方没做」。
5. 交付形态的验收要在交付形态本身上跑，不能在开发形态上推演。

**三个必须主动说的边界**：没有跨机调度 / 没有 worktree 真并行（刻意）/ 业务侧效率指标无基线不编数字。

**一个必须准备好的自我交底**：见 §9，至少讲两条。
