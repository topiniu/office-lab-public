# Office Lab v0.12.0 · 可切换 Agent 执行引擎

状态：0.12.0为当前正式运行版本；2026-10-23按用户授权整理为GitHub main主版本。完整回归与生产构建通过；交付提交及远端一致性以Git记录和本次发布核验清单为准。开发分支：`codex/v0.12.0-multi-engine`。

## 需求与边界

- 工作台支持 Claude Code / Codex 切换；保留员工 SOP、任务状态机、交接、审批、流式观测、停止与续聊。
- 全局默认引擎作用于新会话；每个运行持久化自己的引擎，旧记录无引擎字段按 Claude 处理，禁止跨引擎复用 session ID。
- 业务工具定义与 SDK 解耦。新增引擎通过注册适配器接入，不在业务编排中增加供应商判断。
- 配置区分执行引擎与模型 ID，模型默认值按引擎保存；不隐式回退到另一供应商。
- 会议、企微人格、标题与通知摘要也须纳入路由，避免切换后仍暗中依赖 Claude。
- 原运行目录不作为测试数据源。测试实例使用独立端口/数据目录，并关闭自动接棒、巡视、目标循环及外部推送。

## 实现设计

执行接口接收提示、工作目录、会话标识、工具、权限及取消信号，输出工作台现有的消息事件契约。保留历史事件形状以兼容旧记录和新旧界面；供应商协议转换只在适配层发生。

Claude 适配器延迟加载 Agent SDK。Codex 适配器通过本地 `codex app-server` 的 stdio JSON-RPC 协议管理 thread/turn，业务工具由宿主调用，审批交回工作台。实验性协议能力须显式握手，错误须可见，不能静默吞掉功能。

## 兼容边界

- Claude 继续加载原 SDK/settings/hooks；Codex 不执行 `.claude` hooks，不提供 Claude Task/Agent 子代理。Lab 的角色 SOP、业务交接和宿主工具继续使用；Codex 项目文档 fallback 支持 `agents.md`/`CLAUDE.md`（按 CLI 自身发现规则）。
- Codex 原生操作不一定走审批回调，因此 Claude allow/deny/ask glob 仅在收到审批请求时匹配，不能宣称全等价。2026-10-22按用户要求，正常bypass员工使用完整访问；只读咨询/无原生工具辅助会话保持只读。非编码职责指令、角色宿主工具白名单保留，关闭环境附带 MCP/插件和原生子代理。依赖 Claude hooks 的流程继续选 Claude。
- Codex 的工具事件和完整消息块实时入流，文本 delta 用于活动保活，不逐字落盘；计费金额、Claude 专属思考 token 估算不伪造。Codex 冷恢复使用本机 CLI 保存的线程，跨机器需另行迁移 CLI 会话数据。
- Codex dynamicTools 属于实验性 App Server 能力；升级 CLI 后应跑 `scripts/check-engine.mjs codex --live --tools`。未支持的协议请求明确拒绝。
- 保存基座配置本身无需重启，只影响新会话。代码升级在空闲时切换并重启；已有任务跨基座续跑需显式使用交接入口。
