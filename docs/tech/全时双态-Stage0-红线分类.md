# 全时双态 · Stage 0 · 红线拆分（永久安全不变量 vs 流程控制）

> **归属**：[`全时双态协作-设计.md`](全时双态协作-设计.md) §14 阶段 0（拱心石·前置）+ §15/§16 的落地。**这是"守航态每个角色能松什么、绝不能松什么"的权威清单**——一切后续（契约、结构门、影子跑）都以它为准。
> **状态**：Stage 0 进行中（2026-08-15）。先做**菲菲**（终极目标最相关：她扛 intake/澄清边界，是守航最需强结构护栏的角色，见时间线 round 11）。其余角色（GG Bond / 迷糊 / 波比 / 菲斯拉 / 小呆呆）后续按同框架补。
> **零引擎改动**：本文件是分类判定，不改任何代码/SOP 正文；它只是为后续"哪条能进契约放松、哪条必须做成结构门"提供依据。

## 判据（两类，非"松/不松"二元，而是"模式能不能调"）

- **永久安全不变量（INV）**：违反它会危及安全/信任/造成不可逆伤害，或**打断多智能体协调的"制度性后盾"**（对应 Anthropic 红队报告《Patterns and problems…》：agent 缺人类的规范/产权/追索，全靠这些结构兜底）。**任何模式（共驾/守航）都不可破，守航态尤其**。
- **流程控制（PROC）**：协调/质量/时序类规则，**某个模式可显式调（松或紧）**，调整须留痕。PROC ≠ "守航必然放松"——有的 PROC 守航照样保留，有的守航反而收紧，有的守航在授权下放松。

> **关键手法（红队报告 + 菲菲自己 SOP 双重印证）**：最安全的那几条**不能只写成 SOP 正文**——菲菲 SOP 自己就有两次"纪律写进 prompt 却没拦住"的事故（2026-07-31 标 `【等你拍板】无` 被误续、2026-08-09 空转）。**INV 里凡"守航态行为会变形"的（如"问老板"→守航变"park"），必须做成结构门**（进 task-archive `gates` + 派工快照信号 + 看板可见，像 `tripartite_review` 那样），不靠角色 prompt 自觉。

## 一、全局永久安全不变量（所有角色、所有模式）

这几条是 lab 的"制度性后盾"本身，**守航放大规模时决定它安不安全的正是它们**（红队："失败取决于环境结构 > 模型性格"）：

| # | 不变量 | 对应红队/设计 |
|---|--------|--------------|
| G1 | **角色隔离 / 不碰非本职生产资源**（菲菲不改生产码、各角色守自己工具边界） | 产权机制；防地盘战 |
| G2 | **不替用户做反悔代价大的业务决定**（v0.11.0 老板 2026-09-29 拍板改写，原文「不替用户决定业务口径」） | 终极目标的硬墙。守航态三种不确定：查得清的自己查、可以反悔的自己定并在验收卡上亮明由老板追认、反悔代价大的 raise_risk 等老板 |
| G3 | **不伪造测试通过 / 不降标换 GREEN**（park 不 relax） | 反假绿；设计 §8/H3 |
| G4 | **交接内容必须真实**（不报"已 push"实未提交） | 防 v5.17 交接卡失实 |
| G5 | **单一事实源即时回写**（任务档案/看板；唯一让人看见发生了什么的通道） | 守航晨检的唯一依据 |
| G6 | **跨员工交接只走方案 B**（禁 Task/Agent/SendMessage 私自 spawn 同名子代理） | 结构性协调后盾；防 rogue 扩散 |
| G7 | **不执行未授权/不可逆动作**（生产发布、生产 DDL、破坏性 Git、真实外部副作用） | 守航可逆天花板；停在最后安全可逆点 |

## 二、菲菲 12 条红线逐条判定

| 红线 | 原意 | 判定 | 守航态怎么处理 |
|---|---|---|---|
| **0** 禁编辑/创建生产代码 | 角色隔离最高红线 | **INV**（G1） | 不变。守航态也绝不碰生产码，改一律 park 给 GG Bond 那条流水。 |
| **1** 不写实现细节 | 需求/技术分界 | **PROC**（两模式都保留） | 不变。质量-角色边界，守航不放松。 |
| **2** 不替用户/业务拍板 | 口径是人的决定 | **INV（G2）＋机制是 PROC** | ★核心。"不决定业务口径"=永久不变量；但"想问就编码 `【等你拍板】` 并**等**老板"这个**机制**是 PROC——**守航态够不到老板 → 变形为"park 到晨检拍板队列"**，绝不改成"自己猜"。**必须做成结构门**（见下）。 |
| **3** 验收标准可测试 | facet 可断言 | **PROC（守航收紧）** | 守航态**更依赖**它（机器门要拿 facet 断言）；不可断言的 facet → 该条不具守航资格。 |
| **4** 不擅自增删范围 | 防 scope creep | **INV（核心）＋机制 PROC** | "不静默扩范围"=不变量（红队"影响面超登记"危险）；机制"进待确认走拍板"→守航变形为"影响面超登记=硬绊线、立即 park"。 |
| **5** 发布说明零术语+三来源 | 发版质量 | **PROC** | 发生在共驾/发布后；守航不触及（守航终点是发测，不发布）。 |
| **6** 权限变更四要素 | 配置员可配 | **PROC** | 权限变更本就是**守航禁入项**（设计 §4 forbidden），守航永不到这。 |
| **7** 跨员工交接只走方案 B | 协调后盾 | **INV（G6）** | 不变。守航态尤其——rogue spawn 在无人时更危险。 |
| **8** 改长行先重读+核验落盘 | correctness 卫生 | **PROC（两模式保留）** | 不变。 |
| **9** 绝不空手收工 | liveness/可观测 | **INV（G5 近亲）** | 不变，守航态收紧：每轮必须以清晰 marker 或**明确 park** 结束，绝不静默。 |
| **10** 看板即时回写（唯一状态源） | 单一事实源 | **INV（G5）** | 不变，守航态是**晨检唯一依据**——没回写=早上你看不见发生了什么=守航失败。 |
| **11** 建档先落骨架别空转 | 反空转卫生 | **PROC（守航收紧）** | 守航态加空转熔断（隔离条目/空转占比超阈→安全中止、提前出晨检）。 |

## 三、菲菲 SOP 结构性那条线（终极目标的真正开关）

菲菲 SOP §140/§153：**「维护表 ≠ 开工；做哪些、何时开工永远是老板在看板的决定；我不触发开工/派工。」**

- 判定：**PROC（守航态在授权下放松的核心那条）**。
- **共驾态**：维持原样——菲菲生成"候选清单"，老板挑、老板派。
- **守航态**：在一份**睡前显式授权契约**边界内，菲菲**可自选并发起**（挑需求→建卡→冻结→走流水）。
- **但下垫的 INV 不动**：G2「不决定业务口径」+ 红线 4「不静默扩范围」——**菲菲自选的只能是"可证明零业务待决"的条目**（七项拷问全 `【已知】+来源`、零 `假设`/零 `缺口`）；任何带 open 的 → park 到晨检拍板队列，绝不猜。

## 四、产出：守航态菲菲「能松什么 / 绝不能松什么」

**能松（PROC，仅守航态、仅在睡前契约授权内、留痕）**：
1. **自选 + 自发起**（松红线 §140「维护表≠开工」）——从 `Ready for Guarded Run` 池按显式字段选，建卡、冻结、派工，不必逐条等老板挑。
2. **不逐条请示归属/优先级**——按老板预设优先级排序（本就已授权，§142/§149）。
3. **三方会审按需**——守航候选默认已澄清冻结；会审可降频（补丁位/纯配置类），但降频显式留痕（红线沿用）。

**绝不能松（INV，任何模式、守航尤甚）**：
1. **G2 不做反悔代价大的业务决定**（v0.11.0 改写）→ 遇 `假设/缺口` 先分类：①查得清的自己查（写依据）、②可以反悔的自己定并 `record_decision` 亮在验收卡上、③反悔代价大的 `raise_risk` 只停那一条。~~park 到晨检队列，绝不猜~~（旧口径：实账自选 4 轮 0 条开工，把能自己想清楚的事也当成了必须问老板的事）。
2. **红线 4 不静默扩范围** → 影响面超登记=硬绊线立即 park。
3. **G3 不降标换绿 / G4 交接必真实 / G5 看板即时回写 / G6 方案 B / G1 不碰生产码 / G7 不碰不可逆动作**。
4. **红线 9 绝不空手收工** → 守航态收紧为"每轮清晰 marker 或明确 park"。

**必须做成结构门、不能只写 SOP 正文的**（菲菲历史证明正文拦不住）：
- **park-不-guess 门**：七项拷问三选一**已有信号**；新增的是"守航态下带 open 的条目不进版本、进 `已跳过`/晨检拍板队列"这条**路由**——落进 task-archive `gates`（如 `guarded_ambiguity_parked`）+ 派工快照信号 + 看板可见，复用 `tripartite_review` 的钉法（时间线 2026-07-29 对策四：方法论必须落到 agent 每次都会读到的结构里）。
- **守航资格门**：`guarded_run_eligible` 等字段在 task-archive frontmatter，机器可判、晨检可审"她判成零歧义并跑了的是哪些"。

## v0.11.0 修订（2026-09-29，老板拍板）：G2 从「不替用户决定业务口径」改为「不替用户做反悔代价大的业务决定」

- **为什么改**：菲菲自选需求的 4 轮守航（08-21×2、08-25、08-26）全部 0 条开工、每轮 park 6~8 条。根因是把「查得清的」「可以反悔的」也归进了「只有老板能定的」，G2 从安全底线变成了效率天花板（设计 §23）。
- **改成什么**：可以反悔的决定员工可以先做，但**必须在验收卡「我替你定了什么」里亮明**，老板一键追认或改掉（改掉会自动把条目交回流水线返工）；反悔代价大的（改线上数据/表结构、动权限、影响钱、对外发消息、推翻已上线规则、删东西）仍是老板的决定，走 `raise_risk`。判据一句话：「做错了，老板说一句话能不能一小时内改回来、不留后遗症？」
- **什么没变**：其余 INV 一条不动——不伪造测试通过、不执行生产动作、不做破坏性 Git、交接必须真实、测试证据绑不可变版本、不静默扩范围（点名即范围）。
- **防滥用的结构**：① 守航态 `park_item` 必须写「为什么只有老板能定」，写不出引擎拒收；② `record_decision` 撞上改线上数据/权限/钱等信号会提醒改走 `raise_risk`；③ 菲斯拉对抗审查「替老板定的」有没有把③类混进②类。
