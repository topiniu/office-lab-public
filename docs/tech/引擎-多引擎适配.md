### 3.158 进程退出不等于继承管道关闭（2026-10-22）

现场：GG Bond会话20261019095816-3d251b（Codex thread 089939b1-5939-5072-af55-1ccee9d777dd）于18:55:37正常收工；Codex本地logs_2.sqlite关联出实际PID46428，该进程最后日志为18:58:30，接近三分钟空闲回收窗口。19:35:30老板问题已落Lab事件，但Codex rollout及进程日志均无新输入；19:42:52 watchdog标记441s静默并abort，之后一直没有自动续跑事件。现场检查对应Codex进程已不存在，Lab仍running/stalled。全程时间为Asia/Shanghai。

明确缺陷：CodexRpc把exited绑定child_process的close事件，异常退出也只监听close；close还依赖子孙进程继承的stdout/stderr句柄全部释放。若主进程已退出而继承管道仍开着，await rpc.close永久等待，codexQuery的finally不返回，consumeStream无法执行clearLive与后续恢复。旧_input已close，后续push静默丢弃，UI却被beginTurn置running。隔离真实Node父子进程复现：父进程exit=0后close不发生，旧适配器回归超时；清理测试自有管道持有者后才完成。该复现证明现有实现的挂起缺陷；历史现场未记录exit/close/PID生命周期，因此不能据此断言具体哪个子进程持有了事故管道，也不能把远程控制的API-key提示或企微认证失败当作本次根因。

修复：单独观测主进程exit，异常退出及时向消费者报错；close仍等待自有进程树终止，再释放本地继承管道，清理设置5秒上限，超限明确抛错，不伪报完成。RPC记录spawn、request/response及耗时、请求超时、process-exit、stdio-close、tree-stop、close-start/complete/timeout；适配器补充turn/input/finally/abort事件，以runId、threadId、PID关联。诊断走server.err.log，禁止写入提示、工具参数、配置、密钥或原始stderr，仅统计stderr字节数。正常空闲退出不会自动重复上一轮任务。

验证：26项引擎/模型/交接回归通过；新回归用真实子进程复现继承管道、验证退出错误能到消费者、输入关闭能释放query以及清理超时不假成功。实际Codex隔离临时目录两轮无工具回复通过，输入结束到清理完成330ms。随后用户明确要求立即上线并恢复原问题：20:38完成重启，新引擎PID13500，2590条历史记录保持，原问题重投一次且旧thread正常resume，已产生实际回复与文件读取结果。生产目录26项回归通过，关联诊断已在server.err.log可见。发布记录见版本文档。历史现场具体管道持有者仍未确定。

选择适配器注册表、公共宿主工具和统一事件契约。业务编排只决定 engine/model，不处理供应商协议；Claude 仍使用原 SDK，Codex 使用本地 App Server 的 stdio JSON-RPC。Codex SDK 的一次性文本执行不足以承载 Lab 的常驻输入、宿主工具和审批回调，因此使用 App Server。没有实现“任意 OpenAI-compatible endpoint 自动等价完整 Agent”的假接口；第三方引擎必须实现工具、取消、恢复及事件适配。

关键不变量是 session ID 的归属：默认基座只作用于新会话；旧记录缺字段视为 Claude；每条新 run 保存 engine，初始化后保存实际 model。交接、排队、自续、巡视和审计使用来源基座；同一 session 不随全局配置切换。配置校验先于原子落盘，不静默降级到另一供应商。

真实协议验证发现三处不能靠猜：① dynamic tool 的 `mcp__` 前缀被 Codex 保留，改为有长度限制的 `lab__` 名称，事件中再映回 Lab 原名；②配置覆盖键的引号会成为名字本身，不使用 `mcp_servers."name"`；③ `config/read` 返回的默认值不一定可原样写回（如空的 timeout），只覆盖需要的 enabled 字段，不复制完整配置。均由真实调用定位，并写入回归/冒烟。

权限并非逐字等价。Claude hooks、settings 和 Codex 的 execpolicy 不互通。Codex 关闭环境附带的 MCP、插件和原生子代理，只挂角色工具；只读/代码锁角色使用只读沙箱，审批进入 Lab 卡片，拒绝扩大权限的请求，工具输入在宿主执行前校验。原生沙箱内操作不一定触发审批回调，因此不能宣称 Claude deny glob 对每一次 Codex 原生命令生效。此边界写入使用说明，默认继续 Claude，依赖 hooks 的流水线不自动迁移。

验证分层：模拟协议测试检查归属/工具/审批/取消；真实 stdio 子进程测试检查报错/超时/清理；真实模型冒烟检查工具调用、两轮热对话与冷恢复；独立 HTTP 实例和浏览器检查设置保存。生产服务、生产数据和外部通知不参加测试。详细证据见 [版本说明](../office-lab-v0.12.0-多引擎.md)。

### 3.152 Claude 不可用时，任务应能交给另一基座继续（2026-10-22）

触发：任务做到一半时 Claude 返回 `503 No available accounts`，自动 resume 仍调用同一不可用服务。只改变全局默认不会改变原 run；跨供应商复用 session ID 也不可行。

取舍：保留 Lab run ID，替换其底层 provider session，而不是克隆整条 run 再改写 callerRunId、ccChildren、guardContract 等图关系。模型本地会话不迁移；旧 engine/session/model 进入 engineHistory，原事件流水保留。工作区、咨询只读、角色权限、守航契约和未完成协作子任务都保持。其他已有同事会话与已排队派工不批量改基座；当前 run 之后新派出的交接沿正常规则继承新基座。

交接摘要由引擎读取已落盘记录确定性拼装，不要求失效模型再总结。包括原始指令、任务档案、最近快照、近期对话/工具调用、委托者和子任务坐标；用户可预览并补充。工具记录只证明尝试过，不能当执行成功的证据；新会话必须核对磁盘与任务档案，不能重放发布或把切换当成额外授权。摘要有长度上限，并非完整上下文迁移。

关键防线：`engineHandoverPending` 先持久化，阻断旧重试、收工接棒、巡视、守航自动续派和重启恢复。取消旧审批、输入与 abort 后，等待消费流 Promise、在途 autoChain 和宿主工具 Promise；15 秒未收束则保持暂停，允许用户重试，不因 UI 已显示 interrupted 就并发开新引擎。期间的协作消息写入 handoverInbox，启动目标会话时注回。迟到的旧流事件只落历史；旧 `/stop` 的六秒兜底必须校验 stream 身份，防止误停已接手的新会话。

切换完成先保存目标 engine、清空 sessionId 和旧 model、保存可恢复的交接种子，再启动新 query。新引擎启动失败如实报错、不自动切回；未得到 sessionId 时仍可从保留种子回复继续。进程重启遇到未完成交接不自动复活旧会话。正在运行的独立服务或远端操作不能用消费流退出证明已取消，摘要要求先查实际状态。

验证覆盖重复提交409、参数拒绝无副作用、超时与显式重试、源执行流/宿主工具收束、旧结果不派下一棒、消息暂存、旧停止计时器失效、正反向新会话、权限/工作区/协作身份保留。另用隔离 HTTP 实例实测活跃流迁移，新旧界面操作及390px窄屏；真实 Codex 在新的 thread 返回 `HANDOVER_OK`。业务发布/外部通知与完整多角色流程未作实盘验证。详见版本文档。

### 3.159 · Codex桌面更新后的可执行文件发现（2026-10-23）

**现场**：23:55 Codex桌面更新后，原`bin/6257d9e8f63c0f2b/codex.exe`已不存在；GG Bond两次启动均报ENOENT。该错误发生在spawn阶段，模型尚未启动，与模型主动性及权限无关。托盘也在相近时段退出，但缺少退出记录，不能据时间相关性认定同一根因。

**对策**：先通过引擎设置接口修复本机CLI路径恢复使用。RPC每次启动前检查可执行文件：有效显式路径保持；裸codex优先PATH中的exe，其次本用户官方安装目录；已失效的官方16位hash安装路径可在同一安装根选择最近的完整CLI。跳过缺少codex.exe的半安装目录；失效自定义路径原样报错，不猜测替换。无需shell字符串执行，模型目录与真实会话共用。

**验证边界**：隔离目录覆盖更新、固定版本、自定义路径、半安装、无候选、PATH优先；真实App Server模型目录验证只读协议，不重投业务指令。此次不修改用户任务或自动重复真实报名。
