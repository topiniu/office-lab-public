### 3.4 权限模型（三次演进）
1. **v0.1**：`--permission-mode` + `settings.json` 静态白名单（`Bash(git push origin feature/*)` 之类精确命令模式）。脆弱、跨机不一致。
2. **v0.2.0**：员工走 `auto` 分类器自主放行，`canUseTool` 把危险/未知命令路由到 **Lab UI 审批卡**（后端端点 + 前端卡）；代码内置 `DANGER_DENY` 全员硬拦致命命令（scoped deny 任何模式恒生效）。
3. **v0.2.1（代码已改，版本号未 bump）**：切到 `acceptEdits` + 显式**三名单** `PERM_ALLOW`/`PERM_ASK`/`PERM_DENY`（内置引擎、不依赖 `~/.claude/settings.json` 是否被 `settingSources` 加载），跨机一致、开箱即用。`ask` 命中 → 审批卡；未命中 → 审批。
- **非编码角色代码锁 `codeLockDeny`**：菲菲/波比禁写 `frontend/**`、`backend/**` 下实现文件（菲菲曾把一个咨询越界改成 347 行 `index.tsx`）。glob 实测坑：必须用 `./x/**` 或 `//abs/**`，无前缀/单斜杠绝对路径都不匹配。
- **bypass 特例**：`bypassPermissions` 下 SDK 在咨询 canUseTool 前就放行 → 不传回调（避免 `CAN_USE_TOOL_SHADOWED` 警告），但仍只下发 deny（红线保留）。

### §3.135 红线通配跨过命令动词去匹配用户数据段：MR description 里写了「merge」，前端发测 MR 被系统性堵死（2026-09-21，run `20260921074152-5a44fd`）

**现象**：老板问「波比速度怎么这么慢」。拆那条 run 发现它 18.2 分钟里有约 2.5 分钟纯粹在原地打转——更要命的是**两个前端 MR 根本没建成**，交付物降级成甩一条「创建链接」让老板自己点，而收工汇报把这件事写成了「glab mr create 被策略拒 → 回退创建链接」，读起来像外部环境限制，不像引擎自伤。

**根因**：`DANGER_DENY` 里禁「程序化合并 MR」的两条模式是

```
'Bash(*glab* merge*)', 'Bash(*glab*mr*merge*)'
```

它们拿**整条命令串**做通配，而 deny 只看字面、**不分「命令动词」与「字符串字面量」**。波比按前端发测 SOP 写的 MR description 是

> 发测 master(经 -master 中转分支 merge dev,无冲突)

那个 merge **只是描述文案**，却让 `glab mr create`（动词是 create）整条命中。他换了 6 种写法连吃 8 次 deny：加 `-R`、换 `GITLAB_HOST`、改走 REST `glab api -X POST .../merge_requests`、把描述里的空格去掉……全部绕不过（去掉空格后由第二条 `*glab*mr*merge*` 接着拦）。后端那条 MR 能建成，**只因为它的描述里碰巧没写 merge**——同一道闸对两个仓给出相反结果，这种「看起来随机」的表现让人几乎不可能往权限规则上怀疑。

而「`-master` 中转分支 merge dev」恰恰是前端发测 SOP 的标准描述 ⇒ **这条红线等于把前端发测 MR 系统性堵死**，只是此前没人把两件事连起来。

**对策**：把模式钉在**动作 token** 上，而不是钉在「merge 这个词」上：

```
'Bash(*mr merge*)'                  // 真·合并子命令（两 token 连写，文案不会撞）
'Bash(*glab*--merge*)'              // glab mr create --merge
'Bash(*glab*--auto-merge*)'         // --merge 匹配不到它，必须单列
'Bash(*merge_requests/*/merge*)'    // REST 合并端点（建 MR 是 .../merge_requests 结尾、不含尾部 /merge，故不误伤）
```

新增 `app/test/merge-deny.test.js`（3 例 15 断言）钉住两侧：MUST_DENY 覆盖 `mr merge` / 前缀挂 cd·env / 中间插 `-R` / `--merge` / `--auto-merge` / REST 端点 / 绕开 glab 用 curl；MUST_ALLOW 直接**照抄那一轮被误杀的三条原始命令**，外加查 MR、本地 `git merge`、`-master` 中转分支的标准做法。

**一般化教训（这条才是要带走的）**：**高危 deny 的通配符不能跨过「命令动词」去匹配用户数据段。** title / description / commit message / 分支名里什么词都可能出现，拿宽通配去扫整条命令串，等于让"用户输入的内容"决定"这条命令算不算高危"。宁可多列几条精确模式，也别用一个宽通配连坐整类正当动作。

**附带两条**：① 与 §3.114 同族——**一次性的确定性失败被重试放大后会改变归因方向**：8 次 deny 让现场读起来像「glab 环境不稳」，真相是一条确定性规则每次都精确命中。② 误伤的代价不只是慢：它**静默降级了交付物**，而降级理由写进汇报后看着完全合理，没有任何一道门禁会对「回退到创建链接」报警。
