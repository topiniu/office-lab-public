# 部署 · 独立部署与跨平台（工作区根 / 首启 / 仓库完整性）

## 公开版：可安装的完整工作台

用 `python3 scripts/export-product.py <新目录>` 从跟踪的应用源码、可复用模板和发行配置生成公开源码快照。发行配置内置产品、开发、QA、发布四位员工，启用本机回环访问，并移除内部地址与第三方工作表标识等私有配置。自动检查通过后，再检查实际发行文件、依赖和启动行为。

公开包首次启动以本机根目录为默认工作区，初始化空任务、会话、附件和员工记忆目录。前端构建产物和后端 API 同源。用户在「设置 → Agent 基座」配置自己的模型，空看板直接提供「派工」入口。放入其他项目时可显式指定包含 Office Lab 的项目根；外部集成由用户按需配置。

GitHub Pages 放安装说明。公开仓库的流水线构建前端、运行引擎测试，并从空白发行目录核对员工列表、配置保存和服务边界。

### §3.102 一个 `path.resolve('..','..')` 让 agent 的工作树逃到仓库外；以及「只有真 clone 一次才发现」的那批坑（2026-08-24，老板要求驱动）

**起因**：老板要求「lab 仓库搬到其他电脑上面能够开箱即用」。听起来是打包/文档活，实际挖出三类性质完全不同的问题——**一个设计缺陷、一个假声明、一堆从未入库的文件**。第三类最致命，也最没法靠读代码发现。

#### 一、设计缺陷：工作区根写死成「上两级」

`server.js:22` 原本是：

```js
const ROOT = path.resolve(__dirname, '..', '..')   // office-lab 的**父目录**
```

而这个 `ROOT` 不只是拼路径用——它是**员工 agent 的 `cwd`**（`startRun` 与会议 `speakOnce` 两处），而员工的 `permissionMode` 多为 `acceptEdits` / `bypassPermissions`。

独立 clone 到 `~/dev/office-lab` 后，`ROOT` 就是 `~/dev` —— **仓库外的任意父目录**。今天在原机器上不出事，纯粹因为两个巧合同时成立：① 默认 `git clone` 出来的目录恰好叫 `office-lab`；② 它恰好嵌在一个当 `ROOT` 用也说得过去的父目录里。于是 `ROOT/office-lab/tasks/x.md` 碰巧解析得到。**目录一改名、或换个嵌套深度，整条任务档案链就全断**。

这既是可移植性问题，也是个越权面：agent 的可写工作树本该收在仓库里，却被默认放到了仓库外一层。

#### 二、枢轴发现：`office-lab/` 前缀已经是「线上协议常量」，不是物理路径

最直觉的修法是「把所有出栈字符串里的 `office-lab/` 统一成真实物理路径」。**这条路是错的**，代价在动手前必须先查清：

- **旧 UI 把它写死在正则里**：`app/public/app.js:2510` 的 `REPO_MD_SRC` 只认 `office-lab/(tasks|templates|roles|docs|memories)/…`；`2627`/`2658`/`2753` 的截图内联只认 `office-lab/app/uploads/…`。而旧 UI 恰恰是**已入库、免构建、"总能跑起来"的兜底主路径**。
- **存量数据全带它**：`runs/index.json` 里 **406 条 `taskFile` 首段 100% 是 `office-lab`**；`tasks/` 下 **53 个档案共 136 处**引用（其中 125 处 `office-lab/tasks`）。
- 反倒是新 UI 前缀无关（`web/src/components/message-content.tsx:19` 只找 `/uploads/`）——它一行都不用改。

所以「统一物理路径」= 让旧 UI 的 md 链接与截图内联在独立模式下**静默失效**，外加迁移 500MB 量级的存量数据。

**正确切法是分三层**（落在新模块 `app/paths.js`，路径根的唯一事实源）：

| 层 | 是什么 | 处置 |
|---|---|---|
| **L** 逻辑/协议 | `office-lab/…` 前缀。落库、`/api/tasks` 的 `file`、`/api/upload` 的 `path`、存量档案、旧 UI 正则 | **冻结，一律不改** |
| **P** 物理 | agent 用原生 Read/Write/Bash 时相对 `cwd` 的真路径 | 只在**出栈给 agent 那一刻**由 `toAgentPath()` 改写一次 |
| **R** 解析器 | 引擎自己读写文件 | `repoCandidates()` 三候选双向容忍 |

L→P 只有三个咽喉，一个都不能漏、也一个都不必多：`makeInputChannel().push`（吃掉全部入栈文本——派工头、任务快照、同事近况、抄送与接棒消息、上传标记）、`startRun` 拼完的 `roleText`（systemPrompt 不走 push）、会议 `speakOnce` 的裸字符串 `prompt`。关键细节：**`appendEvent` 在 `push` 之前落库**，所以落库与前端拿到的永远是 L 形式，旧 UI 正则继续成立。

R 层候选序：① 工作区相对（嵌套模式下 `office-lab/tasks/x.md` 直接命中 = 原行为）→ ② 仓内相对（`tasks/x.md`、`roles/…`）→ ③ **剥前缀后仓内相对**（独立模式下 406 条存量靠这条命中，零迁移）。

**形态探测用标志物、不用「父目录有没有 .git」**：判据是 `backend` / `frontend` / `manage-backend.sh` 三者之一存在。理由是它们本就是 `CODE_ROOTS`（`server.js:121`）与 `MANAGE_BACKEND_SH`（`server.js:1516`）的**定义性事实** —— 判据与「`ROOT` 到底给谁用」同源，不会出现「判成嵌套但兄弟仓其实不在」的中间态。另留 `OFFICE_LAB_WORKSPACE_ROOT` 作逃生阀（也是在原机器上就地验证独立语义的唯一无损手段）。

**本轮最重要的安全属性**：嵌套且目录同名时 `OFFICE_PREFIX === OFFICE_URI_PREFIX`，`toAgentPath` **恒等** —— 原机器行为一字不变。这条写成了断言（`app/test/paths.test.js`），并用「生产实例跑的正是改动前的代码」做了逐字段 diff 佐证。

副产品：`roles/*.md` 与 `.claude/agents/*.md` 里那 10 处路径示例**一行没改**（`buildRolePrompt` 出口统一改写）。改一处出口 > 改十处 md，且后来者新增 md 时不用记住这条规矩。

#### 三、顺带修掉的两个存量 bug

- **给员工的指路指错了目录**：`server.js` 告诉员工去读 `office-lab/runs/<id>.jsonl`，但 `RUNS_DIR` 实为 `app/runs`——员工照它读必然 ENOENT。改用 `officeRel('app','runs')`。
- **`safeResolve` 对仓内相对路径解析错根**：嵌套模式下 agent 给 `tasks/x.md`，原实现解析到 `<monorepo>/tasks/x.md`（读抛 ENOENT，**写则静默落到错地方**）。候选②修掉。同时 `..` 穿越的拒绝语义**一字不变**——这一点是刻意设计的：候选各自按其基准根限界（工作区候选按工作区根、仓内候选按仓根），否则 `../secret` 会经「`OFFICE_ROOT/../secret`」落进工作区根、由抛错变成可读。有正反用例钉着。

#### 四、真 clone 一次才发现的那批坑（本节最重要的部分）

前面两块都是读代码能想清楚的。真正决定「搬过去能不能用」的，是 `git clone` 到 `D:\tmp\ol-clone` 真跑一遍才照出来的东西：

**33 个被引用的文件从未入库。** 不是被 `.gitignore` 忽略，是漏 `git add`：

- `app/ui-contract.js`、`app/e2e-batch.js` —— 工作树的 `server.js` 顶层就 import 它们；
- **10 个 `web/src` 模块**（`dispatch.ts` 被 11 个文件引用、`use-dock.ts` 被 4 个）→ 新 UI 构建在全新 clone 上必然失败；
- 12 份任务档案、2 个模板、4 个 `app/test/*.test.js`。

**口径要说准**（我第一次说错过，当场纠正）：当前 committed 的 `server.js` 是 **5100 行的旧版**、并不 import 那两个模块，所以现在 clone 出来**不会崩**，而是拿到一个**落后约 2000 行的引擎**（工作树 vs HEAD：`+2022 −127`）。真正的风险是**下一步**——一旦提交新 `server.js` 却漏 add 那两个模块，clone 当场 `ERR_MODULE_NOT_FOUND`。

**对策：把它变成机器会喊的告警。** bootstrap 新增步骤 2「仓库完整性」，双向自检：

- **任何机器**：解析 `server.js` 的本地 `import` 并逐个查存在。缺就**硬失败**，且措辞直说「这是仓库本身不完整，不是你的环境问题」并给出该执行的 `git add` 命令——把一个会让接手人怀疑自己环境的错，变成一个指向源头的错。
- **源机器**（有 git）：列出「被引用却未入库」的代码/用例/看板文件，提醒交付前先提交。实测抓到全部 33 个。

#### 五、跨平台首启的分级降级

`scripts/bootstrap.mjs`（纯 Node 内置模块、零依赖、`.mjs`；仓根新增只含 scripts 的 `package.json`，**刻意不设 `type:module`** 以免改变仓根任何 `.js` 的解析语义）。核心原则是**只有「引擎起不来」才硬失败**：

- 硬失败：Node < 18、引擎依赖装不上、SDK 平台二进制缺失、`server.js` 的本地 import 缺失。
- 只告警：Node < 20.19（构建不了 vite，自动转 `--no-web`）、凭据查不到、新 UI 装不上/构建失败、浏览器打不开。

新 UI 的包管理器三级择一：`pnpm` → `corepack pnpm` → `npm exec pnpm@10`，全找不到就跳过、回落到旧 UI（`app/public` 已入库、免构建，且覆盖 5 个配置面板中的 5 个，只差「企微表格降级」那一个只在新 UI）。

**自测照出来的三个真问题**（都是「我以为对、跑一遍才知道错」）：

1. **Windows 上 `spawn` 那些 `.cmd` 垫片不带 shell 会抛 `EINVAL`**（Node 20.12+ 对 CVE-2024-27980 的加固），不带后缀则 `ENOENT`——两条路都不通。症状是本机明明有 corepack 0.33.0，脚本却报「没有可用的 pnpm」。必须 `shell: true`。
2. 改走 shell 后又要**把命令拼成单串、不能传 args 数组**，否则触发 `DEP0190` 弃用告警（shell 下参数只拼接不转义）。拼串安全的前提是「传给这些命令的参数一律不含空格」——已作为文件级约束写进注释，路径只经 `cwd` 传、不进 argv。
3. **凭据预检原来是纯误报**：按「`~/.claude/.credentials.json` 存不存在」判定，而 Windows/macOS 的登录态在**凭据管理器/钥匙串**里、不是文件——本机实测该文件根本不存在，派工却完全正常。改成「能确认就确认，不能确认就说不能确认」，绝不下「没有凭据」的断言。

#### 六、通用教训

1. **「能不能搬」这件事，读代码读不出来，必须真 clone 一次。** 本轮读代码想清楚了路径根与依赖声明两件事，但真正卡死接手人的是 33 个漏 add 的文件——它在源机器上**完全不可见**（本机跑得好好的），在任何静态检查里也不可见（文件确实存在）。只有「从 git 里重新长出一份」才暴露。凡是「交付形态」的验收，都要在**交付形态本身**上跑，不能在开发形态上推演。
2. **一个常量被两种用途共用，是最难发现的耦合。** `ROOT` 同时是「拼路径的基准」和「agent 的工作树」。前一个用途下「上两级」凑巧能用，后一个用途下它是个越权面。拆成 `WORKSPACE_ROOT`（工作树+越权边界）与 `OFFICE_PREFIX`（拼路径）之后，两个用途各自的正确性才能分别论证。
3. **改「看起来是内部实现」的字符串前，先查谁在依赖它。** `office-lab/` 前缀看着就是个物理路径，实际是前端正则 + 400 多条存量数据共同依赖的**线上协议**。判断一个东西是不是契约，标准不是"它长得像不像契约"，而是"有没有别人按它的形状写了代码/存了数据"。
4. **文档里的「零依赖」这类自我描述会腐烂，而且腐烂得无声。** `README.md:160` 一行里同时写错了端口（4700 实为 4800）和依赖（声称零依赖，实则两个 npm 包）。这类声明没有任何机制校验，只在有人照着做且失败时才暴露——而"照着做的人"通常就是新机器上的接手人。所以 bootstrap 的存在本身也是一种文档：**可执行的声明不会腐烂**。

**改动落点**：`app/paths.js`（新，唯一事实源）、`app/server.js`（根定义/三个 L→P 咽喉/两处 `cwd`/启动日志/两个存量 bug）、`scripts/bootstrap.mjs`（新）、`package.json`（新，仓根）、`app/package.json`（补 `zod` + `engines`）、`web/package.json`（补 `engines`）、`app/test/paths.test.js`（新，19 例）、`.gitignore`（补 `/run/`）、文档六处纠错。未改 HTTP 端点 / SSE 事件 / run 形状 / 标记解析等前后端契约；未碰 `tray/office-lab-tray.ps1` 的监管逻辑（见 §3.85）。

**验证**（全部在 Windows 本机实跑，测试实例一律 `OFFICE_LAB_RUNS_DIR` 隔离 + 独立端口，生产 4800 实例全程未动）：
- **V1** `app/test/paths.test.js` 19 例全绿（含「嵌套同名时 `toAgentPath` 必须恒等」这条核心断言、`..` 穿越正反用例、`my-office-lab/x` 这类相似串不误吃）。全量 `npm test` **99/99**。
- **V2** 用 `OFFICE_LAB_WORKSPACE_ROOT` 就地起独立形态：日志 `mode=env prefix=''`；`/api/tasks` 的 `file` **19/19 仍是 L 形式**；L 形式与仓内相对形式**都** 200；`..` 穿越 404。

- **V6** 「嵌套模式零变化」：生产 4800 实例跑的正是改动前的代码（启动于改动前 2 小时），用它当基准与新代码的 4899 实例逐字段 diff `/api/tasks`、`/api/employees` → **完全一致**。（比 `git stash` 干净：不动工作树。）
- **V3** 真 clone 两份（`ol-clone` 与改名的 `ai-office`）→ 铺入工作树状态 → 跑 bootstrap：`npm ci` 真装、平台二进制到位、`mode=standalone workspace=<clone 根>`、**工作树不再逃出仓库**、19 份档案照读、6 位员工工牌命中、越权 404。

## 2026-11-18 公开分发范围恢复

公开包以全部 Git 跟踪文件为起点，仅排除历史任务、员工记忆、会话/附件、个人插件设置与临时调试产物。原版六份角色 SOP、六份 Agent 工牌、模板、托盘与迁移工具全部保留，文档和示例中的业务名称、资源标识、用户路径及网络地址统一脱敏。审计、巡视与默认员工权限沿用原版，外部服务连接由新使用者配置。

公开版的任务和记忆属于每次安装的运行数据，纳入 gitignore 后，原版数据包模式的“任务与记忆已在 Git 中”假设不再成立。因此迁移打包的数据清单补入 tasks/、memories/，恢复仍按 manifest.dataPaths 逐项恢复。教训注入测试用临时合成记忆代替私人历史记忆，保留原有的选择、预算和常驻注入断言。Windows 流水线执行托盘决策层测试、PowerShell 脚本解析和隔离迁移往返验收。
