# 示例项目 · UI 母版

> **这份文件存在的理由**（老板 2026-10-06）：「用示例项目模块作为母版，让迷糊融合业内优秀的 UI/UX 设计去诊断」。
> 新模块（批量管理、项目跟踪……）的每一种页面元素，都先问一句：**示例项目里同一种东西长什么样？**

## 它和另外两份文件的分工

| 文件 | 回答什么 | 形态 |
|------|----------|------|
| `示例项目-视觉设计基线.json` | 按钮/表格这类元素的**数值**（圆角、字号、内边距）在模块里多数是多少 | 机器采的 token，`design_conformance` 用 |
| `示例项目-UX契约.md` | 行为约定（Upload 可粘贴、Modal ⌘/Ctrl+Enter 提交） | 源码静态检查，`ux_contract_check` 用 |
| **本文件** | **每一型页面在示例项目里整体长什么样**（布局、位置、留白、叫法） | 真实截图 + 看得到的要点，`visual_prescreen` 读它、迷糊对照着看 |

## 怎么维护（迷糊）

1. 按下表每一型，到示例项目里找**最有代表性**的一处，截图存 `docs/示例项目需求/00-通用资料/母版/<型号>.png`（1280 宽；需要展开/悬停的截展开后的样子）。
2. 把截图路径填进「截图」列（多张用顿号分隔），「要点」只写**看得到的事实**：位置、对齐、内边距、按钮顺序、叫法——别写「美观大方」这类形容词。
3. 示例项目自己有两种写法并存的，两张都截、要点里写「两种并存，以 X 为准」，别替设计拍板。
4. 母版本身不是完美的：初筛时新页面比母版好的地方照实写「比母版好」。
5. 引擎只认第一列是英文型号（小写加横线）的行；截图列为空的型号会在初筛里标「未采」。
