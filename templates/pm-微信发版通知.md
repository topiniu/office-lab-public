# 微信发版通知（模板 + 范例）

> 产出人：菲菲，PM_RELEASE_NOTES 三件套完成后的**第四件交付物**。
> **只打印在收工汇报里（代码块包裹，方便直接复制进微信群），不写入 CHANGELOG 文件、不落盘。**
> 目的：发版后在微信群里精准告知需求提出人「你要的功能做好了」。

## 格式骨架

```
【v<版本> 发布完成 · <上线日期>】
<一句话概述：本版围绕什么，带来了什么>

🆕 新增功能
1. <条目，业务语言，与 CHANGELOG 口径一致> @<提出人>(<提出人>)
2. …

✨ 体验优化
1. … @<提出人>(<提出人>)
2. …

🐛 问题修复
1. …
```

## @ 规则（核心）

1. **逐条回溯需求来源**：对照该版本原始需求（表格的「提出人/需求人」列、PRD 署名、沟通记录）+ 需求说明/需求确认文档里记录的需求方，判断每条 changelog 条目源自谁提的需求。
2. 源自谁就在**该条句尾**追加 ` @<名字>(<名字>)`（格式照抄范例：`@饭团(饭团)`）；一条对应多人就并列多个 @。
3. **识别不出提出人的条目不 @，宁缺勿错**——@错人比不 @ 更糟。内部技术收尾、开发自主优化类条目通常无 @。
4. 条目文字与《版本发布说明》/CHANGELOG 口径保持一致（同一功能同一个叫法），禁止编码级术语。
