# <模块>-v<x.y.z>-源材料开放项台账（骨架模板）

> 产出人：菲菲。**这份文档回答一个问题：源材料自己标出来的「还没定」，有没有一条不见了。**
>
> 缘起（2026-09-09 项目跟踪 v0.1.0 第二轮）：09-08 那次事故（38 条 facet 对 308 个原型单元）之后
> 上了溯源闸与功能树闸，菲菲补到 facet 100 条 / 映射表 357 行 / 三闸全绿。老板再读一遍 PRD，当场又点出
> 一批没落地的口径——其中「跟单人撤销完成后能不能再发一次链接、唯一键要不要加轮次维」**在 09-08 那份
> 《PRD遗漏与返工清单》里明明写过一次**，09-09 的拍板清单里就没了，没人发现它是怎么消失的。
> 它和 F47「幂等靠库层唯一键(批次+环节+SKC)」还是直接冲突的：撤销完成后再收一次，第二次必被自己的唯一键拦死。
>
> 根因：开放项没有账。它只活在某一轮的某份文档正文里，下一轮重写文档时**静默蒸发**，账面上看不出少了什么。
> 本表就是那本账：**源材料里每一个 ⏳ 一行，每行必须有终态。缺行引擎硬挡。**

## 一、清点（跑 `scan_open_items`，别手抄）

引擎按源材料的**单元原文**逐个扫 ⏳，给每条一个稳定 ID（`<材料id>#<单元key>⏳<序号>`）。
ID 稳定意味着：下一轮重扫，同一个开放项还是同一个 ID——**这就是"它有没有不见"能被机器判出来的原因**。

```
scan_open_items                                   # 不给参数=扫任务档案 source_materials 声明的全部材料
scan_open_items file=office-lab/app/uploads/x.html#doc-d0 id=d0    # 或指定单份材料
```

把它输出的整张表抄下来，只补最后两列。

## 二、台账（一条 ⏳ 一行；缺行 = 引擎硬挡）

> **终态只有三种**，别自创：
> - `已决` —— 决议列写**口径 + 出处**（谁、哪天、在哪定的）。没有出处的"已决"跟"我按默认猜的"在账面上分不开。
> - `待拍` —— 决议列写**它在哪份拍板清单的第几条**。待拍不落到清单上就是丢了；**开工前必须清零**。
> - `不做` —— 决议列写**理由**。"不做"和"漏了"必须分得开。
>
> 一条 ⏳ 可能在原型里出现在两个单元上（标题行 + deep 段），引擎已在同单元内去重；跨单元的同一问
> （如「负责人必填/选填」同时挂在绑定表列与绑定弹窗上）各占一行，第二行的决议列写「同 <另一个 ID>」即可。

## 三、自检（收工前跑，errors 清零才准交棒）

```
validate_req_substance      # 台账闭合是它的判据③（硬）；顺带看①扇入 ②阈值 ④区块专属 三项
```

- **缺行**：源材料有 N 条 ⏳、台账只有 M 行 → 差额逐条点名。补齐，别改扫描器。
- **终态不合枚举**：只认 `已决 / 待拍 / 不做`（引擎做同义归一：已定/已拍→已决，待确认/待定→待拍，二期/范围外→不做）。
- **已决没写出处 / 待拍没写落到哪 / 不做没写理由** → 各自点名。
- **终态=待拍还有剩** → 软提示，但它们必须同时出现在任务档案的拍板清单里，**开工前清零**。

## 四、为什么不是"在需求文档里写一节待确认"就够了

写过。09-08 写在《PRD遗漏与返工清单》里，09-09 重写文档时那节没了。
文档正文是会被重写的，账不会——**账的判据是"上一轮的每个 ID 这一轮还在不在"**，这件事只有稳定 ID + 逐行台账能判。
`需求说明与验收标准.md` 的 §五「待确认事项」仍然要写（那是给会审与老板看的**读物**），
但它不是账：2026-09-09 那份的 §五 写着"全部已收敛、无遗留阻塞项"，同一天任务档案里躺着 13 条待拍。
