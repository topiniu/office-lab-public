# 守航任务契约（Guarded-Run Contract）· <run_name>

> **这是什么**：全时双态「守航态」启动时，由老板睡前（或离场前）一次性签发的**任务级授权快照**。它取代"逐步请示"——菲菲及下游据它自主推进、引擎据它机器拦截越权、次日据它审计"实际行为有没有超界"。设计依据 [`docs/tech/全时双态协作-设计.md`](../docs/tech/全时双态协作-设计.md) §5；红线可松/不可松见 [`docs/tech/全时双态-Stage0-红线分类.md`](../docs/tech/全时双态-Stage0-红线分类.md)。
> **铁律**：契约一旦启动，本轮守航期间**员工不得自行扩张**（改 selection/authorization/limits/forbidden 一律无效、且属越权计数）。要改 = 老板显式重签。
> **落法**：本文件是**人读 + 机器读**的双用契约；散文段供老板/晨检人阅读，下方 ```yaml``` 块是员工与次日审计的授权事实源（⚠ 现阶段**引擎不解析、不机器拦截**它——Stage 4 拦截层 2026-08-15 已撤，见设计 §18 发现 #1）。填好后与任务档案同放 `tasks/`（命名 `<日期>-<版本>-守航契约-<run_name>.md`）。
> **v0.11.0 守航自助托管（2026-09-29）**：① 新增 `goal:` 块——链停了、活没干完，引擎的**目标循环**接着派人，直到每条都「做完且验收卡四格齐 / 等老板拍高危事项 / 试尽后隔离」；② 口径从「遇歧义 park，不猜」改成**三种不确定**（查得清的自己查、可以反悔的自己定并亮在验收卡上、反悔代价大的才 raise_risk 等老板）；③ 老板早上看**验收卡**（侧栏「验收台」），晨检包降为底稿。机制见 [`docs/tech/全时双态协作-设计.md`](../docs/tech/全时双态协作-设计.md) §23。
> **常规路径已自动化**：看板侧栏「🌙 守航开工」入口会按本模板**自动签发**一份契约（引擎 `server.js:issueGuardedContract`，落 `tasks/<日期>-守航契约-guarded-NN.md`）。**本模板是字段语义的事实源——改这里的字段要同步改那个生成器**（反之亦然）。手填本模板只用于自动化覆盖不到的特殊授权（如临时放开某项 authorization）。

## 二、机器契约（引擎按此执行 + 拦截 + 审计）

```yaml
mode: guarded_run
run_name: <版本>-guarded-01
starts_at: <ISO8601+08:00>
deadline: <ISO8601+08:00>                 # 到点必须安全收束、出晨检包

selection:
  source: Ready for Guarded Run           # 只从合格池选，禁从普通待处理池随意挑
  max_items: 3
  max_parallel_items: 2                    # ＝跨角色重叠上限（开发B∥QA A），非单角色分身（H8）
  max_changed_repositories: 2
  priority_order: [P0, P1, P2]

authorization:                             # 只有列 true 的动作被允许；未列即禁
  create_version: true
  create_feature_branches: true
  commit_development_branches: true        # 仅开发分支，绝不碰 master/release
  run_automated_tests: true
  integrate_candidate_branch: true         # 进 guarded/<版本>-rc，不碰生产 release
  deploy_test_environment: true            # 守航终点；停在此，不发布生产
  deploy_production: false                 # 永远 false（守航不自动发布生产）

limits:
  max_dev_qa_rounds_per_item: 2            # 超限→隔离，不再自行换方案（G3 park 不 relax）
  max_integration_rounds: 2               # 版本级回归环也封顶（防整晚打转）
  max_environment_retries: 2
  max_runtime_minutes: 480
  max_tokens: <整数>                        # ★成本熔断（H7）：本轮总输出 token 硬顶，超则安全中止
  stop_new_items_before_deadline_minutes: 60

forbidden:                                 # 命中即拦 + 记 guard.violation.forbidden_action
  - production_release
  - production_ddl
  - permission_model_change
  - destructive_git
  - force_push
  - business_scope_inference               # ★不替老板做**反悔代价大**的业务决定（G2，v0.11.0 拆开）：查得清的自己查、可以反悔的自己定并 record_decision 亮在验收卡上；只有代价大的 raise_risk 等老板
  - external_side_effects                  # ★真实企微/真机/三方副作用（含测试路径！见资格审 H4）

failure_policy:
  business_ambiguity: fact_self_check_reversible_decide_costly_raise   # v0.11.0 三种不确定：查得清→自己查；可反悔→自己定（record_decision）；代价大→raise_risk，只停那一条
  repeated_test_failure: quarantine_item   # 超返工上限 → 已隔离 + 保留分支与失败证据
  environment_failure: retry_then_continue_others
  suspected_boundary_violation: stop_action_continue_safe_work
  agent_idle_stall: quarantine_and_queue   # 夜间本应升级老板 → 隔离该条 + 进晨检队列（H6，不死等）
  mass_quarantine_or_stall: safe_abort_early_report   # 隔离数/空转超阈 → 安全中止、提前出晨检（熔断）

exit:
  target: test_environment                 # 或 rc_ready（若基建只能靠合 master 发测，见设计 §7 → 先停 RC_READY）
  final_state: awaiting_human_acceptance
  produce_acceptance_cards: true           # v0.11.0：老板早上看验收卡（一个需求一张：做完没 / 长啥样 / 动了哪些老功能 / 要你拍的高危事项）
  produce_morning_report: true             # 底稿：晨检包仍由引擎从机器事实装配（H5），折叠在验收卡「看底稿」里

goal:                                      # v0.11.0 守航目标循环
  loop: active                             # active=链停了没干完就自动派人接着做 / shadow=只记录不派 / off=关（旧契约无此块 → 按 shadow）
  max_goal_turns: 8                        # 最多自动续跑几轮；同样的局面连续 3 次续跑没推进 → 判卡住、停下交老板
  done_when: acceptance_cards_complete     # 每条要么「做完且验收卡四格齐」，要么「等老板拍高危事项」，要么「试尽后隔离」
```
