# <版本> 晨检验收单 · <日期>

> **这是什么**：**一个版本一份**，跟着任务档案走。守航终点不是「发布完成」，而是「已就绪、等待人工接管」——一睁眼点开任务卡的「晨检验收」页签，几分钟内做三选一（三选一只记录进档案时间线，**不改 gates、不触发发布**）。
> **★诚实铁律（H5）**：本单**由引擎从机器事实装配**（登记表 / 覆盖矩阵 / 三红灯台账 / 契约 diff / park 台账）——**不取 agent 自述**。agent 叙述另置文末「自述栏」并标注，绝不与机器事实混排（被 reward-hack 出 GREEN 的 agent 会照样报 GREEN）。

## 〇、本单缺了哪些料（引擎自检，缺席≠通过）

逐条列出没接通/没记录的章节。**缺料照样出单**——标满「未接通」的单也远好过没有；但缺席一律按「未验证」读，不得当成「已通过」。同时列出本版已停产的轮次级包，防止误把旧口径当今天的结论。

## 一、一眼摘要（版本级 · 机器汇总）

版本与派生状态（只认 `fm.gates` 布尔位 + 条目终态，**绝不回读 `fm.status`**——它会滞后）、条目总数、已交付/待验收/在测/开发中、**卡住几条**、待你拍板的口径问题、守航轮次链，以及三红灯的**两个数**：`本版累计`（整体健康）与 `最近一轮`（昨夜）。只给累计读不出「连续三轮全 0」的晋级判据，只给单轮就退回了「一个版本裂成 N 份」。

## 二、版本条目全表（← 需求条目登记表 × 覆盖矩阵 × 门禁）

**行集 = 任务档案的「## 需求条目登记表」全量**（唯一状态源，与看板圆点同源）。覆盖矩阵/台账/门禁只补列：绿/总、RED 校准、证据 commit、需人工必验。
- 「看板状态」直接印登记表原文，**不再翻译成第二套词汇**。
- 矩阵里有、登记表里没有的 REQ 单列 `orphanReqs`，**绝不混进主表**——「这一版有几条」不许有第二个答案。

## 三、卡住与待拍（这一节决定你今天要说哪几句话）

阻塞/打回/隔离的条目逐条给「卡在哪」；未关闭的**真歧义 park** 逐条给「拟定口径（你不拍就按这个执行）」；机器门未过的逐条写明「未验证 ≠ 通过」。已交付的条目不再报放行门（那一问早已作废）。

## 四、老板验收决策（三选一）

整版通过 / 部分通过 / 整版打回 + 必答清单。**放在第四章是刻意的**：读到第三章末信息已闭合，决策不该再隔着两章审计材料。

## 五、最近一轮守航（增量 + 审计）

昨夜那一轮：契约点名 / 本轮真动过（逐条标出处：台账·门禁·证据 runId·进入登记表）/ 新进登记表 / **差集「点了名却一整轮零机器痕迹」**；随后是三红灯明细与契约 vs 实际 diff。

## 六、历史轮次汇总（一轮一行）

run_name / 起 / 契约点名 / token / 越权 / 假绿 / 超预算 / 已结算。
