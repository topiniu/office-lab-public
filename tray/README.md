# 望子成龙小学 · 系统托盘（Windows）

把「只能在命令行 `node server.js`、关了终端服务就断」升级成**常驻系统托盘应用**：托盘托管服务进程，关掉终端也不受影响，还能一键启停 / 看状态 / 看日志 / 开机自启。

> 零安装：托盘本身只用 Windows 11 自带的 PowerShell 5.1 + .NET（WinForms/Drawing），不装任何 npm 包或第三方软件。仅需系统里已装好 **Node.js 18+**。

> **全新 clone 的机器请先跑一次仓根的 `node scripts/bootstrap.mjs`**：托盘只管拉起进程，**不装依赖**——引擎的 npm 依赖（`@anthropic-ai/claude-agent-sdk`、`zod`）和新 UI 的 `web/node_modules` 都得先就位。托盘那步「`web/dist` 缺失就 `pnpm build`」也假定 `web/node_modules` 已存在，全新 clone 上会直接失败；bootstrap 首启时把产物构建好，托盘那步就自然跳过了。
>
> macOS 目前**没有**等价的常驻方案（launchd + 菜单栏在下一轮做），先用 `node scripts/bootstrap.mjs` 前台跑。

## 快速开始

双击 **`启动托盘.cmd`**（推荐，不依赖 Windows Script Host，会有一瞬间的窗口一闪）。

> **那一闪是引导进程，不是托盘。** 脚本开头会把自己重启成一个 `CREATE_NO_WINDOW` 实例、引导进程随即退出——所以**常驻期不存在任何可被误关的终端窗口**（真身 `MainWindowHandle=0`、`GetConsoleWindow()` 返回 `0x0`）。`.cmd` / `.vbs` / 开机自启的 `.lnk` / 右键「用 PowerShell 运行」都走这条路。想连那一闪都没有，得把系统「默认终端应用」改成 `Windows 控制台主机`——那是全局设置，托盘不去动它。
>
> 也可改双击 `office-lab.vbs`。若某台机器被杀软/组策略禁用了脚本宿主（`.vbs` 双击弹窗后没反应），就用 `启动托盘.cmd`。
>
> **看不到图标？** Windows 11 默认把新托盘图标收进任务栏的「隐藏图标」里——点任务栏时钟左边的 **^** 展开，找到状态圆点，拖到外面即可常驻显示。

- 任务栏右下角出现一个**状态圆点图标**，服务随即被拉起。
- 图标颜色即状态：🟢 运行中 · 🟠 启动中 · 🔴 进程在但无响应 · ⚪ 未启动。
- **单击图标（左键）** = 开/关**悬浮窗**（再单击一次收起）。最常用的动作给最轻的手势。
- **双击图标** = 打开控制台（浏览器开 `http://127.0.0.1:4700`），与以前一致。
  > 单击动作会延后一个系统「双击时长」再执行——双击的第一下也会触发单击事件，不延后的话每次双击都会顺带把悬浮窗翻一遍。双击到达即撤销这次待执行的单击。
- **右键图标** = 菜单：

| 菜单项 | 作用 |
|--------|------|
| ● 运行中 · :4700 · 在跑 N · 内存 M MB · 上线 X | 顶部实时状态行（只读） |
| 打开控制台 | 浏览器打开工作台首页 |
| 悬浮窗 ▸ | 全局置顶小窗（内嵌 WebView2 加载工作台 UI），看别的东西不用来回切窗口；**等价于左键单击托盘图标**。子项：显示/隐藏（置顶）· 重新加载页面 · 窗口置顶（可关）· 半透明（85%）· 重置位置与大小。关窗=隐藏可再召唤；位置/大小/置顶/透明度记忆在 `app/runs/tray-config.json`。首次打开会用 Win11 自带的 WebView2 运行时 + 仓库内 `tray/vendor/webview2/` 的组件 |
| 启动 / 停止 / 重启服务 | 手动管服务（停止会连带杀掉在跑的 claude 子进程树，不留孤儿） |
| 查看服务状态 | 弹气泡：端口 / PID / 上线时长 / 在跑数 / 内存 / 待审批 / Node 版本 |
| 查看运行日志 | 记事本打开 `app/runs/server.out.log` |
| 查看错误日志 | 记事本打开 `app/runs/server.err.log`（崩溃/报错才有内容） |
| 打开安装目录 | 资源管理器打开本 `tray/` 目录 |
| 开机自启 | 勾选后登录自动拉起托盘（在「启动」文件夹放一个快捷方式） |
| Windows 通知（审批/收工回执） | 默认开；员工请求审批、收工/异常时弹**原生 Toast**，可在通知里直接回执 |
| 崩溃自动重启 | 默认开；服务异常退出时自动拉起（60s 内超 5 次则停手，防死循环烧钱） |
| 退出（并停服） | 关闭托盘并停止服务 |

开机自启 / Windows 通知 / 崩溃自动重启的开关状态持久化在 `app/runs/tray-config.json`。

## Windows 本地通知与回执

除了原有的 Bark 手机推送，托盘常驻期间还会弹 **Windows 原生 Toast**（与 Bark 相互独立，不受 Bark 开关影响），并支持在通知里**直接回执**——无需先打开浏览器：

| 场景 | 通知内容 | 通知里的回执按钮 |
|------|----------|------------------|
| **员工请求审批**（危险命令待放行） | 🙋 员工名 + 命令摘要（reminder 常驻直到处理） | **同意** / **拒绝**（直接放行或拒绝）· **打开控制台** |
| **员工收工·待你拍板** | 🙋 员工名 + 待拍板事项 | **文本框 + 发送回复**（一句话催他继续/拍板）· **打开控制台** |
| **员工收工 / 异常 / 中断** | ✅/❌/⏸ 员工名 + 任务名 | **打开控制台** |

- **审批同意/拒绝**：等价于在控制台审批卡点「同意/拒绝」，`POST /api/runs/:id/permission`；处理后该通知自动撤下（若已被别处/超时处理也会撤下，避免点到过期的）。
- **快速回复**：等价于运行详情底部输入框回复，`POST /api/runs/:id/reply`（会 `--resume` 续同一会话）。
- **打开控制台**：系统直接开浏览器到工作台首页。
- 实现：托盘每 ~4s 轮询 `GET /api/notifications?since=<游标>`（返回当前挂起审批 + 增量收工事件），据此弹/撤 Toast；按钮点击经线程安全队列交主线程回调后端，稳。
- 关掉某类通知：目前「Windows 通知」是总开关。托盘启动前的历史收工事件不会被回放（只从启动那一刻起提醒）。
- 若系统不支持 WinRT Toast（老 Windows），自动回退为托盘气泡提示（无内联按钮）。

托盘每 4 秒轮询服务的健康端点 **`GET /api/health`**，据此刷新图标 / 提示 / 自动重启判断。该端点也可被任意外部监控探针直接调用：

## 生命周期约定

- **托盘托管服务**：托盘负责拉起并守护 `node server.js`；**经右键「退出（并停服）」退出托盘 = 停服**。这是最贴近「托盘应用」的模型，最简单。
- **托盘被非正常杀掉时（任务管理器强杀、旧版本里误关终端窗口）：服务不会跟着停。** 实测过——`Quit-Tray` / `Stop-Server` 一行都不会跑，而 `CreateNoWindow` 起的 node/vite 是孤儿进程、继续跑到底（托盘没有 JobObject，`server.js` 也不守望父进程）。所以那种情况下**丢的是控制面**（托盘图标、悬浮窗、health 轮询、Toast 审批回执、崩溃自动重启），不是服务本身。下次启动托盘会发现端口有主、自动转「监控模式」接管那些孤儿，右键「重启服务」可收编成托管。
- **互为看护（2026-09-09 起）**：托盘盯引擎（health 轮询 + 崩溃自动重启），**引擎也反过来盯托盘**（`app/tray-watchdog.js`，每 2 分钟用托盘那把命名 mutex 判活一次；不在了就用 `CreateNoWindow` 拉起一个，并在 15s 后回头复核）。两个都死则由「开机自启」兜下一次登录，**谁都不是单点**。三条刻意的约束：**只恢复不引入**（引擎必须先见过托盘活着才会拉，不会在你只想 `node scripts/bootstrap.mjs` 前台跑的机器上凭空弹一个托盘）、**判活只信命名 mutex**（不枚举进程比命令行）、**探不到 ≠ 不在**（PowerShell 起不来/超时时不动手，免得变成 spawn 风暴）。冷却 60s、30 分钟内最多拉 5 次，超限即停手并在引擎日志点名。环境变量 `OFFICE_LAB_TRAY_WATCHDOG=0` 可关。
  > 你主动右键「退出（并停服）」不会被它复活——那条路会先把引擎停掉，**引擎都没了自然没人来拉**。所以「引擎活着 + 托盘不见了」本身就等价于「托盘意外死亡」，判据天然干净。
- 服务进程以隐藏窗口启动，stdout/stderr 分别落到 `app/runs/server.out.log` 与 `server.err.log`（每次启动覆盖写）。
- 端口默认 `4700`，跟随环境变量 `OFFICE_LAB_PORT`；监听地址保持 `server.js` 默认的 `0.0.0.0`（局域网 / Tailscale 仍可访问），健康探测走 `127.0.0.1`。

## 开发与测试

托盘的**纯决策层**在 `lib/tray-logic.ps1`（无副作用：不写日志、不弹气泡、不起进程、不读 `$script:*`），由 `test/tray-logic.tests.ps1` 的 22 条断言覆盖：

```bash
npm run test:tray     # 仅托盘（PowerShell，零依赖、不用 Pester）
npm run test:all      # 引擎 783 条 + 托盘 22 条
```

覆盖的三处**都出过真事故**，改它们之前先跑一遍：崩溃重启限流（判错＝烧钱死循环）、探活三振裁决（判错＝2026-08-20 那次「崩溃好几次」幻觉）、通知游标推进（判错＝Toast 链路被一条坏事件永久毒死）。

写 `.ps1` 两个必踩的坑：**带中文注释的文件必须存成 UTF-8 with BOM**（Windows PowerShell 5.1 默认按 ANSI 读，无 BOM 会中文乱码并报"字符串缺少终止符"）；**`Join-Path` 只接两个位置参数**（多段拼接是 PS7 才有，必须嵌套）。

⚠ 别在 `office-lab-tray.ps1` 里再写一份同样的判断——两份实现必然分叉。逻辑进 lib、脚本只负责把决策落地。

## 常见问题

- **双击没反应 / 图标没出现**：
  1. 先展开任务栏 **^「隐藏图标」**看图标是不是被折叠进去了（Win11 默认行为）。
  2. 用 **`启动托盘-调试.cmd`**：它在**可见窗口**里跑托盘，任何报错都会显示出来（红字），窗口不关托盘就一直在。
  3. 看诊断日志 **`app/runs/tray.log`**：每次启动都会记录「启动→找到 node→拉起 node→进入消息循环」，卡在哪一步一目了然；致命错误也会记进去。
  4. 若原来用 `office-lab.vbs` 双击弹窗后没反应，多半是杀软/组策略禁了 Windows Script Host——改用 `启动托盘.cmd`（不走 WSH）。
  5. 确认命令行能跑通 `node app/server.js`；再看 `app/runs/server.err.log`。执行策略拦截无需担心，启动器已带 `-ExecutionPolicy Bypass`。
- **启动后多了个常驻终端窗口 / 关掉它托盘就没了**（2026-09-09 前的版本）：根因是 Win11 的「默认终端应用」若为 Windows Terminal，新建控制台会被**交接**给 `WindowsTerminal.exe`、**窗口属于另一个进程**，`-WindowStyle Hidden` 和脚本内的 `ShowWindow(SW_HIDE)` 都管不到它（`GetConsoleWindow()` 返回的是替身窗口，藏掉它屏幕上毫无变化）。现已改为自我重启成 `CREATE_NO_WINDOW` 实例，从根上不创建窗口。判断有没有生效看 `app/runs/tray.log`：应能看到 `已自我重启为无窗口实例（子进程 PID …）` 紧接着 `本进程无控制台窗口（无窗可误关）`。**若看到 `SW_HIDE 后控制台窗口仍可见` 或 `自我重启为无窗口实例失败`，说明降级了，那个窗口关不得。** 完整根因与判据选择的教训见 `docs/tech/引擎-健壮性与接管.md` §3.129（并翻掉了 §3.105 的一个结论）。
- **端口已被占用**：若 4700 上已有服务（比如你之前在终端里起的），托盘不会重复拉起 node（避免僵尸进程），而是**转为监控模式**盯着它，并弹气泡提示；等那个服务停了，托盘会自动接管拉起自己的。要让托盘完整托管，先停掉终端里的那个再点「重启服务」。
- **端口被占**：说明已有一个服务实例在跑（可能是旧终端里的）。先关掉旧的，或改 `OFFICE_LAB_PORT` 后重启托盘。
- **想彻底停掉**：右键 →「退出（并停服）」。
- **手动调试托盘**：`powershell -NoProfile -ExecutionPolicy Bypass -Sta -File tray\office-lab-tray.ps1`（会带一个 PowerShell 窗口，便于看报错）。
